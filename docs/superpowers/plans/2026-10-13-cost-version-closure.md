# 产品成本版本闭环实施计划

> **For agentic workers:** 使用执行计划和测试驱动技能；存储/API与页面按文件隔离，主代理整合验收，不让子代理提交或访问 NAS。

**Goal:** 补齐 PRD 已确认的成本有效期、历史版本和修改审计，保留现有经营事实。

**Architecture:** 既有运营 SQLite 追加不可变成本版本与恢复事件；当前成本由有效日期解析，原接口兼容。现有成本后台提供版本录入和连续历史，不重建系统。

**Tech Stack:** Next.js 16、TypeScript、React、SQLite、Zod、Vitest，无新增依赖。

**Spec:** `docs/superpowers/specs/2026-10-13-cost-version-design.md`

## Global Constraints

- 不修改已发布历史利润、原报告、密钥、容器或调度；构建期间保持既有NAS配置，全门禁后仅按用户最后要求备份更新原env镜像标签，容器由用户重建。
- rc.11 标签固定 c75f3cf，不覆盖或重新构建。下一补丁用新候选分支/标签。
- 含税/未税成本固定13%换算不变，试算税0默认也不变；两者不能混用。
- 原覆盖与旧未知生效日期保留；恢复源成本不得删除历史。
- 不扩大个人权限体系、不冒充自然人审计、不新增主导航。

## Review Focus

- 未来及失效版本不能误用于当前试算；前一版本不能在新版本失效后复活。
- 同日连续修订、重复保存和批量冲突：历史有完整事实，失败无半批更新。
- 升级旧表与旧内部调用：旧成本不丢失，不虚构历史日期。
- 回退报告不删除新成本/人工历史；历史实际利润不随当前成本变动。
- 敏感写操作不能仅依靠客户端校验，不泄漏原始会话或数据库异常。

## 决策

- 该缺口由两次源码核对确认，不是新增 ERP 或臆测性功能；通用编辑已明确排除成本字段，不需无关改造。
- 用户要求自主推进，沿用已批准PRD和既有架构；不重新要求用户选择限流、表结构等实现细节。
- 以不可变版本与日期解析补齐需求，不只追加时间戳审计来冒充有效成本历史。
- 初轮聚焦集成33条通过（存储9、route14、UI10），主代理实际复跑。生产构建先因Next16不接受可选GET请求参数失败，改为必填Request后14条route回归及生产构建/类型检查通过；不是关闭类型门禁。
- 原子读取决定：金额与editVersion来自同连接同事务 `readProductCostSnapshot`，避免旧金额配新令牌；真实第二进程写锁测试已执行。
- 独立审查发现并进入一次修复轮：P1整目录严格SKU限制导致整页失败及写后报错；P2报告换版后恢复回显旧源成本；P2同价续期/来源变更无法保存。独立UI复现2条通过，目录错误因审查fixture未完成不当作执行成功，由原作者追加真实red→green。
- 状态展示裁定：同未来生效日已永久被后续修订替代的记录不能再标“未来生效”，按业务日期可信度升为P2在同一轮修复；只改状态，不改变当前选值。
- 恢复语义裁定：恢复版本按生效日参与既有时间轴，不暗中取消更晚的计划；需要取消/更改计划时追加相应日期版本，不删除历史。代价是“恢复”并不等于清空所有未来计划，必须在页面/说明明确。
- 历史附带editState裁定：历史页游标固定上界，附带状态不用于编辑，暂不要求历史及附带状态同一时点；所有可编辑金额与token仍必须原子快照，避免实际覆盖竞态。
- 性能边界：当前读取取得写锁并重建兼容投影，历史按SKU分组扫描。暂无真实NAS规模证据，不冒称性能验收；本轮不为假定规模另建缓存/索引系统。真实NAS负载仍属外部验收。
- 旧镜像边界：仅保留当前值投影，不理解新生效/截止日，跨日不能保证其成本语义正确。回退旧镜像时不得进行成本决策/编辑，必须保留 `product_cost_versions_v1` 并重新使用日期语义兼容的镜像；不删新表换取回退。
