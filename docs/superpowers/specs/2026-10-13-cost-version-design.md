# 产品成本版本设计

依据：PRD V2.0 第4节、6.3和7.2。独立只读审查确认现有成本表仅保留最新覆盖值；没有生效期、历史或修改审计。补齐既有后台，不增加前台入口，不重算已经核验的历史经营利润。

## 业务规则

- 沿用当前含税人民币、未税人民币、美元成本及固定13%换算；不新增财务公式、税率或自动汇率。
- 新保存与恢复操作追加不可变版本。每版记录 SKU、动作、成本、来源说明、生效日期、可选截止日期、记录时间、共用账号与不可逆会话标识。
- 生效及截止为明确的日历日期，截止日包含当天。默认生效日为当前日期，用户可以选择历史或未来日期；未来版本不提前应用，失效版本不继续应用。
- 同 SKU 按生效日及同日修订顺序决定适用版本；新版本生效后旧版不重新复活。历史保留同日修订，不能只留最后一条。
- 恢复源成本也追加版本，表示从该日起跟随已发布目录来源；保存恢复时的来源成本与报告版本用于历史核查。不是删除旧审计，也不是恢复业务数据库。
- 旧覆盖保留，迁移/基线记录明确“历史生效时间未知”，不能以 updated_at 伪造过去业务生效日。未知历史不能冒充按日期准确匹配的成本。
- 保存日期、来源和成本是同一事务；批量任一 SKU 冲突全部拒绝，保留页面草稿。使用服务端版本标识检测并发，不静默覆盖。
- 当前产品资料、清货及试算仍只读当前有效成本；历史销售/实际利润继续读原报告，不按当前成本反算。

## 兼容与接口

- 使用既有运营 SQLite，追加版本表；不更改 Prisma、账号、路径、数据卷或 worker 调度。
- 保留现有 list/save/delete/apply 函数及内部调用兼容。扩展可选日期、版本元数据和只读历史查询；现有调用不伪称有可验证的个人身份或原始报价。
- GET 当前值保持 items；指定 SKU 查询连续历史，返回 nextCursor。提供当前编辑版本标识，未来版本也影响该标识，防止未察觉计划被覆盖。
- 网页保存/恢复必须登录、同源 JSON、真实日期/来源及版本校验；校验失败不能调用存储。不返回原始异常、文件路径、密码或原始 Cookie。
- 不把通用主数据编辑的未知字段当作成本写入；独立成本入口仍是唯一网页成本入口。
- 旧镜像不理解新时间规则：保留原表兼容当前值，明确回退镜像后的成本编辑限制，不宣称旧版支持未来/有效期。不得删除新版本表。

## 页面与验收

既有成本工作台增加紧凑的生效日、截止日、来源输入和按 SKU 展开的版本历史。正常阅读默认收起；不将人工覆盖 SKU 数标作版本数量。恢复前显示目标范围和日期；错误/冲突保留草稿。手机控件上下排列，历史连续加载，有清晰键盘焦点。

使用临时合成 SQLite 验证旧数据兼容、保存/恢复历史不丢失、当前/历史/未来/失效日期、同日修订、空值与真零、批量并发回滚、鉴权/同源及审计不保存会话原文。额外证明历史利润读取不被成本编辑修改。来源权限、真实报价与 NAS 恢复仍单独验收。
