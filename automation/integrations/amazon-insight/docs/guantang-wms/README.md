# Measureman Commerce OS：产品收敛与冠唐仓库整合需求

状态：统一需求稿，仓库首期已实现

更新时间：2026-09-30

本文档是当前产品需求的统一入口。它整合运营前台、单 SKU 经营简报、供应链追溯、新品利润试算、冠唐仓库模块、积加数据接入、手机端和 NAS 部署要求。若下方内容与早期方案冲突，以本文档的最新口径为准；关联文档用于保存接口细节和设计依据。

## 1. 目标

在 Measureman Commerce OS 的管理员后台实现与当前业务相关的轻量仓库管理能力，连接国内仓库、跨境发货、Amazon 在途和 FBA/AWD 库存。

该模块不复制冠唐云的界面、文案和品牌设计，只复用通用仓库业务流程。实施期间冠唐仍是国内仓库事实来源；只有完成历史迁移、并行对账和正式切换后，本站才能成为新的库存事实来源。

普通成员前台继续聚焦：

- 运营总览。
- SKU 经营简报。
- 供应链追溯。
- 新品利润计算器。

入库、出库、盘点、调拨、审核、同步和差异处理仅在管理员后台提供。

最终产品结构：

```text
普通成员前台
├── 运营总览
├── 经营简报
├── 供应链追溯
└── 新品利润计算器

管理员后台
├── 数据中心
├── 仓库与库存
├── 采购与入库
├── 出库与发货
├── 广告与成本
├── 新品调研
└── 团队与权限
```

选品仓保留但默认折叠，不与日常运营入口平铺。普通成员登录后默认进入运营总览；登录页不提供公开注册，首个管理员由系统初始化，后续成员由管理员创建。

## 2. 可行性结论

现有项目已经具备产品资料、采购订单批次、发货历史、汇总库存、用户账户、文件导入、版本快照和经营分析，因此可以在现有架构上增加仓库模块。

当前项目还不是事务型 WMS。国内库存只有 SKU 汇总值，没有完整的“仓库—库位—批次—单据—库存流水”，也缺少盘点、调拨、单据审核、仓库权限和不可篡改审计记录。

推荐复刻约 70% 的日常仓库能力，不复刻与现阶段业务关系较弱的完整 ERP 功能。

## 3. 数据源职责

### 冠唐云

正式切换前，冠唐负责国内仓库实物账：

- 货品、仓库和库位。
- 采购订单和供应商。
- 入库、出库、调拨和库存调整。
- 批次、库存成本和物理在库。

### 积加/Amazon

- 市场、ASIN、MSKU 和平台 SKU。
- 销售、售价、广告和退货。
- FBA/AWD 库存。
- 跨境在途和 Amazon 接收结果。

### 本站

- 冠唐货品编码与 Amazon SKU/ASIN 的映射。
- 国内出库与 Amazon 发货批次的关联。
- 批次余额、FIFO 分配、库存对账和异常处理。
- 经营分析、供应链追溯和新品利润试算。

## 4. 第一阶段功能范围

### 4.1 基础资料

- 多仓库和库位。
- SKU、条码、名称、规格和单位。
- 单品尺寸、重量、箱规、箱尺寸和箱重。
- 供应商。
- 冠唐货品编码、SKU、MSKU 和 ASIN 映射。
- 数据启用、停用和最后同步时间。

### 4.2 入库管理

- 采购入库。
- 退货入库。
- 调整入库。
- 入库草稿、待审核、已审核和已作废。
- 入库单关联采购订单、供应商、仓库、库位和批次。
- 审核通过后才增加库存。
- 作废使用反向库存流水，不删除原始流水。

### 4.3 出库管理

- Amazon 发货出库。
- 样品、报废、退货和其他出库。
- 关联市场、Amazon 发货批次和货件编号。
- 按实际入库时间提供 FIFO 批次建议。
- 一个出库 SKU 可以消耗多个入库批次。
- 审核通过后才扣减库存。
- 默认禁止负库存。

### 4.4 库存管理

- 按仓库、库位、SKU 和批次查询库存。
- 批次入库数量、累计出库、调整数量和当前余额。
- 库龄、最老批次和呆滞库存。
- 全量库存流水。
- 物理库存与批次余额对账。
- 未知来源库存和未分配出库单独显示。

### 4.5 盘点与调整

- 创建盘点单和冻结盘点范围。
- 录入账面数量、实盘数量和差异。
- 盘盈、盘亏、报废及原因。
- 管理员审核后生成库存调整流水。
- 已结账期间不允许直接修改历史单据。

### 4.6 仓库调拨

- 调出仓库、调入仓库和库位。
- 待审核、待调出、在途、待调入和已完成状态。
- 调出确认后减少原仓库存。
- 调入确认后增加目标仓库存。
- 在途调拨数量不同时计入两个仓库。

### 4.7 权限与审计

- 系统管理员。
- 仓库主管。
- 仓管员。
- 普通成员。
- 按仓库控制查看、开单和审核权限。
- 创建人、修改人、审核人、操作时间和修改前后值。
- 导入、同步、手工调整和系统计算使用不同来源标识。

## 5. 暂不复刻的功能

- 应收应付和完整财务账。
- 生产管理与 BOM。
- 年度预算控制。
- 固定资产和领用管理。
- 序列号级一物一码。
- 云打印中心。
- OA 审批和组织架构同步。
- 多语言和多账套财务核算。

这些能力只有在出现明确业务需求后才单独评估，避免把当前项目扩展成完整 ERP。

## 6. 目标数据模型

第一阶段至少需要以下实体：

| 实体 | 用途 |
| --- | --- |
| `warehouse` | 仓库资料 |
| `warehouse_location` | 库位资料 |
| `warehouse_product` | 冠唐货品与本站 SKU 映射 |
| `supplier` | 供应商资料 |
| `purchase_order` / `purchase_order_line` | 采购订单及明细 |
| `stock_document` / `stock_document_line` | 入库、出库和调整单据 |
| `inventory_lot` | 入库批次和成本层 |
| `stock_movement` | 不可变库存流水 |
| `outbound_allocation` | 出库明细消耗的批次和数量 |
| `transfer_order` / `transfer_order_line` | 仓库调拨 |
| `stocktake` / `stocktake_line` | 盘点及差异 |
| `inventory_balance` | 仓库、库位、SKU、批次余额缓存 |
| `warehouse_permission` | 用户仓库权限 |
| `audit_event` | 操作和审核记录 |
| `sync_cursor` / `import_batch` | API 或文件同步状态 |

`stock_movement` 是库存事实账；`inventory_balance` 只是可重建的查询缓存，不允许绕过流水直接修改余额。

## 7. 库存口径

需要分别保存：

```text
国内物理在库
待审核入库/出库
未完成采购
已出库待发运
跨境在途
FBA/AWD 库存
```

不得把冠唐“可用库存”直接作为国内物理库存，因为可用库存可能包含尚未到仓的采购订单。

批次余额：

```text
批次剩余 = 已审核入库 - 已分配出库 + 已审核库存调整
```

SKU 对账：

```text
所有批次剩余 + 未知来源库存 = 当前物理在库
```

差异必须进入异常中心，不得自动摊给最新或最老采购订单。

## 8. 出库来源分配

关联优先级：

1. 冠唐出库明细直接提供入库批次或采购订单。
2. 入库、出库和 Amazon 发货存在相同业务单号。
3. 同仓库、同 SKU 按实际入库时间执行 FIFO 推算。
4. 管理员人工确认。
5. 无法分配时保留“来源待核对”。

系统直连、单据关联、FIFO 推算和人工确认必须使用不同标识。推算结果不能显示为系统确认。

仓库管理

## 10. 冠唐数据接入

### 优先级

1. 冠唐官方只读 API 或 Webhook。
2. 固定模板的 Excel/CSV 定时导入。
3. 仅在私有部署且冠唐正式支持时使用只读数据库副本。

网页抓取和浏览器自动化不作为生产同步方案。

### API 未确认前的文件清单

- 货品主数据。
- 仓库和库位。
- 当前物理库存。
- 批次库存。
- 采购订单及明细。
- 入库单主表和明细。
- 出库单主表和明细。
- 盘点、调整和调拨明细。

导入流程必须为：识别 → 校验 → 预览 → 对账 → 发布。导入失败时保留上一版有效数据，不把库存更新为零。

## 11. 新品利润计算器联动

用户先选择市场和 Amazon 类目，然后系统按以下顺序匹配其余字段：

```text
明确选择的 SKU/ASIN
→ 同型号或同父体
→ 同类目、同尺寸/重量区间的相似 SKU
→ 市场与类目默认值
→ 要求用户输入
```

自动来源：

- 冠唐：采购成本、箱规、箱尺寸、箱重和供应商。
- 积加：售价、市场、ASIN 和 Amazon 包装资料。
- 版本化费率表：市场和类目佣金、FBA 配送费。
- 本站预设：头程路线和费率。

默认广告费率 15%、退货率 1%、税率 0%，不计算危险品和电池附加费。每个字段显示来源、数据日期和置信度。缺少售价、成本、尺寸、重量或箱规时不得按零继续计算。

## 12. 迁移步骤

### P0：确认数据与接口

- 获取冠唐当前套餐的 API 或正式导出文档。
- 确认批次、库位、审核状态和成本字段。
- 完成冠唐货品编码与 SKU/ASIN 映射。
- 确认物理库存、可用库存和待执行采购的口径。

### P1：只读镜像

- 导入货品、仓库、采购、入库、出库和库存。
- 建立批次余额、FIFO 分配和异常中心。
- 网站只查询，不在本站改变库存。

### P2：并行对账

- 每日比较冠唐和本站的仓库/SKU/批次余额。
- 跟踪新增入库、出库、调拨和调整。
- 解决历史未知来源库存和单据缺失。

### P3：网站开单

- 开放入库、出库、盘点和调拨草稿。
- 管理员审核后生成库存流水。
- 若冠唐提供写入接口，则同步回冠唐；否则仍以冠唐为唯一记账端。

### P4：正式切换

- 确认期初库存和未完成单据。
- 冻结冠唐新增业务操作。
- 导入最终余额并签署对账结果。
- 本站成为唯一库存事实来源。

不能长期允许冠唐和本站同时修改库存，否则会形成双主账并持续产生差异。

## 13. 验收标准

- 入库和出库只有审核后才影响库存。
- 任意库存变化都能追溯到单据、操作人和库存流水。
- 任意出库 SKU 能显示来源采购订单/入库批次，或明确标记未分配数量。
- 仓库、库位、SKU 和批次余额可由库存流水重建。
- 批次余额与物理库存可以每日对账，差异不会静默摊销。
- 调拨在途库存不会同时计入调出仓和调入仓。
- 未完成采购不会计入物理在库。
- 导入或同步失败时保留上一版有效库存。
- 普通成员不能开单、审核、调账或修改仓库资料。
- 手机端核心仓库操作在 390px 宽度下无页面级横向滚动。
- 普通成员一级导航不超过四项，登录后默认进入运营总览。
- 运营总览和经营简报以销售额而不是销售件数作为主要经营口径。
- 经营简报默认不平铺全部 SKU，任意 SKU 仍能通过搜索或父体筛选打开。
- SKU 卡片能同时展示历史售价、销售额、销量校验、广告依赖、退货、仓储、利润、库存和季节性证据。
- 新品利润计算器按市场和类目使用对应费率，自动字段显示来源和日期。
- 库存、采购、发货和新品调研的原始明细只在管理员后台提供。

## 14. 当前待确认事项

- 当前冠唐套餐是否支持第三方 API，是否需要额外付费。
- API 鉴权、IP 白名单、限流、分页和历史数据范围。
- 是否支持更新时间游标或 Webhook。
- 出库明细是否能返回实际消耗的入库批次或成本层。
- 当前租户是否已开通批次和库位功能。
- 是否允许固定模板自动导出到 NAS。
- 正式切换后冠唐历史数据保留和导出方式。

在获得正式接口资料前，不创建猜测的冠唐 API 客户端，也不提交任何冠唐账号、Token 或 API Key。

## 16. 运营总览需求

### 16.1 页面目标

用户应在 30 秒内回答：

1. 当前销售额、实际利润和利润率如何。
2. 相比上期发生了什么变化。
3. 最值得进一步查看的是哪些 SKU。

### 16.2 顶部控制

- 市场：US、CA、MX 和双站/多站视图。
- 周期：本月、上月、近 3 月和近 12 月。
- SKU 搜索：SKU、MSKU、ASIN、产品名和父体。
- 数据状态：销售、广告、库存、冠唐和积加的最后成功同步时间。
- 双站金额默认按站点和原币分面展示，未配置带日期汇率时不得直接相加。

### 16.3 第一屏指标

只保留六个核心指标：

1. 销售额。
2. 实际利润。
3. 实际利润率。
4. 广告销售占比。
5. 退货率。
6. 库存覆盖天数或健康 SKU 占比。

销售件数、FBA 数量、AWD 数量、在途数量和国内库存不作为第一屏 KPI，只在证据层使用。

### 16.4 趋势和行动队列

- 展示近 12 个月销售额和实际利润趋势。
- 辅助展示广告销售占比、退货率和仓储费占比。
- 总览简报只显示最需要调整的五条建议。
- 建议对象限制为 5–10 个明显变化或高贡献 SKU，不加载全量 SKU 表格。
- 每条建议必须包含触发指标、数值、周期和可进入的 SKU 证据页。

## 17. 经营简报与单 SKU 卡片

### 17.1 默认展示范围

经营简报默认展示不超过 20 张卡片，优先选择：

- 最近完整月销售额贡献前 20% 的 SKU。
- 销售额环比绝对变化超过配置阈值的 SKU。
- 利润为负或利润率低于目标的 SKU。
- 广告销售占比或广告花费占比异常的 SKU。
- 退货率、仓储费或库龄异常的 SKU。
- 可确认库存覆盖不足或过高的 SKU。
- 数据过期、缺失或映射异常的 SKU。

阈值必须配置化。全部 SKU 通过搜索、父体和问题类型筛选访问，不在页面底部连续平铺。

### 17.2 卡片内容

每张卡片默认在一屏内显示：

- SKU、产品名、父体、市场、数据周期和新鲜度。
- 最近完整月销售额、实际利润和利润率。
- 近 6 个月销售额趋势。
- 当前售价、近 6 月均价和价格变化。
- 销量趋势，仅用于校验价格变化导致的销售额波动。
- 广告销售占比、广告花费占比、ACOS 和 ROAS。
- 退货率、退款率、主要退货原因。
- 仓储费及其占销售额比例。
- FBA 可售、AWD、已确认在途、国内库存、未完成采购和覆盖天数。
- 季节位置：旺季前、旺季中、淡季或数据不足。
- 最多三条带证据的简短建议。

建议不替用户直接下最终结论，而是说明发生了什么、依据是什么、下一步应核对什么。

### 17.3 季节性

- 使用 SKU 月销售额作为主序列。
- 至少 12 个完整月才展示季节性，24 个月以上为高置信度。
- 月均售价变化超过 20% 时同时展示销量趋势。
- 数据不足时显示“数据不足”，不得自动判断旺季。

### 17.4 SKU 深度证据

卡片展开或详情页分三层：

1. 经营摘要：销售额、利润、售价、广告、退货、仓储和库存结论。
2. 分析证据：历史趋势、季节性、库存结构、退货原因和利润构成。
3. 管理员明细：采购订单、发货历史、广告活动、工程参数和 Listing。

SKU 详情必须补充历史发货日期、市场、批次、箱数和数量。采购、发货、Listing 和工程参数默认折叠，不占据首屏。

## 18. 成员供应链追溯

该页面只读，用于回答：

- 某次出库包含哪些 SKU。
- 每个出库 SKU 分别来自哪些采购订单或入库批次。
- 当前国内库存由哪些采购订单组成。
- 某张采购订单已经入库、出库和剩余多少。
- 当前关联是系统确认、单据关联、FIFO 推算还是人工确认。

页面提供三个视图：

1. 出库追溯：按出库单/发货批次查看 SKU、数量、箱数和采购订单拆分。
2. 库存订单构成：按 SKU 查看各采购订单的入库量、累计出库、调整量、余额、成本和库龄。
3. SKU 时间线：采购下单 → 国内入库 → 仓库存放 → 出库 → 跨境在途 → FBA 接收。

顶部支持 SKU、采购订单号、出库批次和供应商搜索，并按仓库、时间、状态和关联可信度筛选。成员不能修改库存、订单状态或来源分配。

## 19. 管理员业务后台

### 19.1 数据中心

- 积加同步、冠唐同步和 Excel 兜底导入。
- 测试连接、立即同步、同步历史和异常中心。
- 上传前识别文件，展示影响范围和数据预览。
- 发布前校验，发布后生成版本，支持恢复历史版本。
- 原始文件与生产快照分离，失败不得覆盖当前有效数据。

网页手工上传需要自动识别库存规划、销售利润、广告、产品成本、产品明细、新品调研和发货文件。表格结构无法确认时进入人工映射，不静默猜测。

### 19.2 库存后台

- SKU 清单支持仓库、市场、库存风险、类目和关键词筛选。
- 大表使用无限下滑/虚拟列表，不使用传统翻页。
- 季节库存合并为库存视图的子页面。
- 用可视化连接 FBA、AWD、跨境在途、国内库存和未完成采购。
- 明确区分物理在库和可用库存，防止重复计算。
- 补货建议目标为 FBA + AWD + 已确认在途能够覆盖未来约 90 天；国内库存和未入库采购单独显示，不重复计入。

### 19.3 采购与发货后台

- 采购计划和发货计划同时展示国内、跨境在途及海外库存结构，不只显示数字表格。
- 过期或已经实际完成的历史采购任务标记为已完成，不继续进入行动队列。
- 发货计划展示建议量、可发量、箱数、目标市场和覆盖变化。
- 任意建议都必须能下钻到销量依据、现有库存、在途和采购订单。

### 19.4 产品成本与新品调研

- 成本计算到最终净利润和净利润率。
- 产品成本、新品候选和订单明细使用无限下滑/虚拟列表。
- 新品调研完整解析全部有效行，不限制为前五条。
- 管理员可手工新增、编辑和停用新品候选。
- 新品调研大表留在后台；普通成员使用独立的利润计算器。

### 19.5 广告后台

- 前台只显示 SKU 级广告依赖和效率。
- 后台保留广告活动、曝光、点击、转化、花费和预算明细。
- 默认展示行动队列：高花费无订单、库存风险、ACOS 异常和可扩量对象。

## 20. 新品利润计算器完整要求

### 20.1 使用流程

1. 选择市场，默认 US，可选 CA 和 MX。
2. 选择 Amazon 类目。
3. 可选选择已有 SKU/ASIN、父体或相似产品。
4. 系统自动匹配可确认字段，只展开缺失或低置信度字段。
5. 用户确认输入后计算，不自动创建产品或写回外部系统。

### 20.2 自动匹配

匹配优先级：

```text
明确选择的 SKU/ASIN
→ 同型号或父体
→ 同类目、同尺寸/重量区间的相似 SKU
→ 市场与类目默认值
→ 要求用户输入
```

- 积加提供市场、ASIN、当前售价和 Amazon 包装资料。
- 冠唐提供采购成本、箱规、箱尺寸、箱重和供应商。
- Amazon 版本化费率表按市场、类目、售价、生效日期计算佣金。
- FBA 配送费按市场、尺寸分段、计费重量和生效日期计算。
- 本站头程预设按市场、路线、运输方式、箱规和箱重计算。
- 广告默认 15%，退货默认 1%，税率默认 0%。
- 不计算危险品和电池附加费，并在结果页明确提示。

市场和类目不能单独确定真实利润。全新品仍需真实售价、采购成本、尺寸、重量和箱规，或者由用户明确选择相似 SKU 作为估算来源。

### 20.3 输出

- 单件净利润和净利润率。
- 盈亏平衡售价。
- 最大可接受广告费率。
- 采购、头程、佣金、FBA 配送、广告、退货和利润成本瀑布。
- 每个输入值的来源、日期、置信度和是否手工修改。

## 21. 数据同步与质量要求

### 21.1 积加

- 首次同步产品、最近 24 个完整月经营表现、库存、采购和仓储费。
- FBA 库存建议每 4 小时同步。
- 当月/上月经营、订单和退货每日同步。
- 广告最近 3 天逐日重拉。
- 未完成采购每 6 小时同步。
- 页面只读取本地标准快照，不直接等待外部 API。

### 21.2 冠唐

- 优先使用官方只读 API/Webhook。
- 未开通 API 时先使用固定模板 Excel/CSV 导入。
- 每日进行仓库/SKU/批次全量库存对账。
- 冠唐未正式切换前仍是国内物理库存事实源。

### 21.3 数据血缘和失败处理

每条关键数据保存来源、外部 ID、市场、统计周期、币种、同步时间和原始状态。API、Excel、手工覆盖和计算值必须可区分。

- 外部接口失败时继续显示最近一次成功数据并明确标记过期。
- 不能把缺失值默认为零后继续给出建议。
- 同一任务重跑必须幂等，不生成重复月份、订单或库存流水。
- 金额和库存冲突进入异常中心，不静默覆盖。
- 库存超过 8 小时未更新显示黄色，超过 24 小时显示红色。
- 经营、广告和退货超过 36 小时显示黄色，超过 72 小时显示红色。

## 22. 手机端与交互要求

- 390px 宽度下不出现页面级横向滚动。
- 普通成员使用底部四项导航：总览、简报、供应链、计算器。
- 总览 KPI 使用两列卡片，趋势图支持点击查看数值，不依赖悬停。
- SKU 卡片默认折叠证据，筛选使用抽屉或底部面板。
- 表格在手机端转换为卡片或关键列，不强行压缩全部列。
- 无限列表使用虚拟渲染，保持筛选条件和滚动位置。
- 仓管员手机端优先支持扫码查货、入库、出库、盘点和调拨确认。

## 23. 报告和下载

- 经营简报支持生成文字与图表结合的 PDF。
- PDF 使用与网站相同的数据周期、币种和指标口径。
- 每张 SKU 卡片最多给三条建议并附数据依据。
- 报告显示生成时间、数据来源、新鲜度和已知缺失。
- 下载中心保存报告版本，不覆盖历史文件。

## 24. 部署与安全约束

- 生产环境继续使用 NAS Docker Compose 和版本化镜像。
- 应用、SQLite、运行时报告、上传文件和导出文件必须持久化挂载。
- 镜像升级不得覆盖 NAS 数据目录。
- Cloudflare Tunnel 只指向应用容器的内部 HTTP 服务，不暴露数据库或管理端口。
- 健康检查至少验证应用启动、数据库可访问和标准数据目录可读。
- 外部 API 凭证仅通过 NAS Secret 或服务器环境变量注入，不进入 Git、镜像、日志和浏览器。
- 管理员同步、库存审核、盘点和调整均记录审计事件。

## 25. 综合实施优先级

### P0：数据、权限与口径

- 确认冠唐接口/导出能力和积加租户字段。
- 建立 SKU、MSKU、ASIN、冠唐货品编码和父体映射。
- 补齐管理员权限、同步审计、数据来源和新鲜度。
- 固化销售额、利润、库存、在途和采购口径。

### P1：前台收敛

- 普通成员导航收敛为四项。
- 总览改为六个核心 KPI 和五条重点建议。
- 经营简报改为可搜索的单 SKU 卡片，不默认列出全部 SKU。
- SKU 详情按摘要、证据和管理员明细分层。

### P1：供应链只读镜像

- 导入冠唐货品、仓库、采购、入库、出库、批次和库存。
- 建立库存流水、批次余额、出库分配和对账异常。
- 提供成员只读供应链追溯。

### P2：新品利润计算器与后台整合

- 上线市场/类目费率表和自动匹配。
- 合并库存、采购、发货和季节库存后台。
- 完成新品调研编辑、产品成本和广告行动队列。

### P3：仓库作业与正式切换

- 开放入库、出库、盘点和调拨。
- 完成手机扫码和仓库级权限。
- 并行对账通过后决定是否替代冠唐。

### P4：报告、性能和完善

- PDF 经营简报。
- 大表虚拟列表、缓存和历史数据按需加载。
- 根据真实缺口评估序列号、打印、生产/BOM 或 OA 审批，不提前实现。
