# Measureman 运营工作台完整需求文档

版本：v1.0 草案

更新日期：2026-10-08

适用项目：现有 Measureman Commerce OS

实施原则：沿用现有页面、接口、数据结构和部署方式，分阶段扩展，不重建整套系统。

本文件统一替代此前积加接入文档中的冲突口径：所有人共用一个登录账号；前台不按父体展示；取消总览五条建议和 PDF 经营简报；库存、采购、发货、仓库与供应链保留在折叠后台。这里描述目标需求，不代表自动同步、外部授权或新分析功能已经完成。

## 1 产品目标

将网站从报表集合收缩为日常运营工作台。使用者进入后能先看整体经营变化，再找到值得核查的 SKU，查看支持该变化的事实，记录采取的动作并在下一周期复核。

核心流程是：运营总览发现变化 → SKU 卡片核查依据 → 后台查看必要明细 → 记录动作 → 后续复核。新品利润试算是独立入口，不与真实经营利润混在一起。

产品应回答以下问题：

- 当前站点销售额、实际利润和利润质量发生了什么变化。
- 哪些 SKU 对变化贡献最大，问题是否持续，证据是否完整。
- 销售变化与成交价、广告、退货、仓储、季节性、供货分别有什么关系。
- 哪些 SKU 值得进一步研究未来三个月的销售提升机会，而非直接承诺增长。
- 当前数据更新到何时，哪个来源失败，页面是否仍在使用旧版本。
- 新品在指定市场、类目和物流条件下，预计利润是否成立。

销售额是前台主指标；销量件数作为分析和补货依据保留，不删除。网站给出简短、可核查的建议，不替使用者自动作出调价、投放、采购或发货决策。

| 领域 | 目标 |

### 明确不做

- 不增加父体汇总或父体筛选，不以父体替代 SKU 判断。
- 不恢复总览五条建议，不开发 PDF 经营简报。
- 不新增管理员和普通成员的功能分级；仍校验有效登录会话。
- 不直接修改 WPS 源表，不自动下采购单、发货单，不操作广告或售价。
- 不复刻完整冠唐云商业系统，不引入新的任务平台、数据库或重复认证系统。
- 不依赖 Mac 常驻浏览器、人工登录 Cookie 或 Codex 会话维持 NAS 自动同步。
- 不把全部 SKU 常驻总览，不新增独立演示页面。
- 不在利润试算中计算税费、危险品或电池专项费用；涉及此类商品时提示不适用。

## 3 账号与使用方式

所有人共用一个既有登录账号、功能权限和工作区。优先沿用现有共用账号选择逻辑及 `SHARED_LOGIN_EMAIL` 配置，不删除旧账号、数据库或历史任务。

所有读写运营接口仍要求有效会话；凭证保存等敏感写操作继续进行 HTTPS、同源和请求格式校验。不因取消角色分级而取消认证。

共用账号意味着无法可靠辨认真实操作者。记录可包含自填经办人，但标为自报信息，不宣称具备个人身份审计能力。掌握共用账号的人均能访问经营数据并修改来源配置，应仅向可信使用者提供账号。

### 运营总览

默认站点 US。CA、MX 仅在有有效经营数据时显示可用状态；不存在的库存或费用不得借用 US 数据补齐。

页面从上到下安排：

1. 站点、经营月份、数据截止时间和轻量来源状态。
2. 销售额、实际利润、利润率三个主指标；广告销售占比、退货率、库存覆盖三个辅助指标。
3. 最近六至十二个月真实销售额趋势。
4. 变化入口：利润变化、销售变化、广告待核查、供货风险、增长机会待核查。
5. SKU 搜索，输入后最多预览三张卡片，继续查看跳转到带条件的简报。

首页默认不展示任何 SKU 列表，不设置五条建议。变化入口显示对应数量及必要的金额影响，不堆叠长篇结论。点击后将站点、周期和问题条件传递至简报。

当月指标标记“截至某日”，只与同长度且可比较的历史期间比较。缺少历史日粒度时，不将当月未结束金额直接与上月整月生成下降警报。完整月份按完整月份比较；同比需要对应历史覆盖。

趋势缺少月份时留空并说明，仅有一个月时显示单月值，不制造曲线。不得用件数乘当前售价回填历史销售额。站点间不直接相加不同币种。

### SKU 经营简报

基本单位是“站点 + 已确认 SKU”。底层保留店铺、MSKU、ASIN 和日期，映射不明确时不强行合并。

默认优先展示需要核查的 SKU，必须真实过滤，不只是把全部 SKU 重新排序。支持全部、销售变化、利润变化、广告、退货仓储、供货风险、增长机会待核查等现有筛选的扩展。支持 SKU、名称、ASIN、MSKU 搜索。

默认加载二十张卡片，下滑继续加载二十张，保留可键盘操作的“加载更多”作为备用；不使用页码。筛选变更取消旧请求，返回后保留筛选、展开和滚动位置。排序、过滤和记录标识稳定，避免重复或漏项。

单卡默认内容：

- 产品名称、SKU、站点及必要的识别信息。
- 销售额、实际利润、利润率、历史成交均价、广告销售占比、退货率六项事实。
- 一至两句建议，附比较周期、关键依据和下一步核查动作。
- 数据不全、历史不足、库存过期等必要提示。
- 展开详情及记录动作入口。

卡片展开后分三个区域，而不是跳转大量新页面：

| 区域 | 内容 | 展示约束 |
| --- | --- | --- |
| 销售与价格 | 最近六个月销售额、件数、成交均价、已核验当前售价、季节性 | 当前售价与历史均价分开；历史不足明确提示 |
| 广告与成本 | 广告归因销售、广告投入、ACOS、退货、仓储和可核验成本 | 归因窗口、费用覆盖和数据来源可查看 |
| 供货支持 | 当前 FBA、AWD、已确认在途、预计到达、国内及采购背景 | 实际可售、转运库存和计划值分层，标明各自日期 |

SKU 卡片优先呈现经营信息，历史发货保留后台入口。完整费用缺失时，不绘制假完整的利润瀑布图。详细依据可折叠，但缺失状态和关键风险不能藏在折叠区。

### 数据更新页

在线来源卡片位于上方，Excel 上传和旧格式导入放在次级折叠区。

积加、WPS 库存、WPS 新品分别显示以下状态，不共用一个模糊“已接入”标识：

| 状态维度 | 内容 |
| --- | --- |
| 配置 | 未配置、已配置、配置不可读取 |
| 授权 | 未检查、通过、凭证失败、白名单失败、部分接口无权限 |
| 任务 | 排队、执行、重试、待审核、失败、取消、完成 |
| 发布 | 未发布、已发布、部分来源沿用旧版本、已回退 |
| 时间 | 最近尝试、最近成功、实际业务截止时间、当前使用版本 |
| 完整性 | 站点、期间、已取页数、有效记录数、重复数、未匹配数 |

按钮区区分“测试连接”“立即拉取”“查看预览”“确认发布”“启用自动同步”“暂停自动同步”。首次完成授权、店铺映射和样本对账后才允许启用自动发布；运行中的同步不得通过重复点击重复启动。

错误显示可执行的处理说明和运行编号，不返回含密钥、临时下载地址或客户信息的原始日志。来源故障时经营页仍可使用最后有效版本，并显著标记时间和故障，不用整页报错掩盖问题。

任务已知总量才显示进度百分比，否则显示阶段、页数和记录数。暂停只停止后续调度，不删除数据；取消在安全检查点终止，发布开始后不得中断为半批数据。

## 5 视觉和交互设计

采用苹果风格的清晰层级、留白、轻边框和渐进展开，沿用现有组件及系统字体，不复制 Apple 品牌素材。设计参考：[Apple 布局指南](https://developer.apple.com/design/human-interface-guidelines/layout)。下述尺寸与配色是本项目约定，不是引用 Apple 的强制要求。

| 项目 | 设计约定 |
| --- | --- |
| 桌面布局 | 沿用约 224px 侧栏、64px 顶栏、1320px 内容宽度上限 |
| 颜色 | 浅灰 #f5f5f7、白 #ffffff、深文字 #1d1d1f、辅助文字 #6e6e73、交互蓝 #0071e3 |
| 层级 | 销售额和利润优先，辅助指标收敛；不增加装饰横幅或高密度彩色卡片 |
| 手机 | 菜单抽屉、三个底部入口、安全区适配；卡片单列，指标适量分行 |
| 可访问性 | 正文优先 14px 及以上；主要触控目标至少 44px；键盘焦点可见 |
| 状态表达 | 加载、无记录、无权限、部分缺失、过期和错误分别表达 |
| 图表 | 标币种、单位和时间；不用颜色作为唯一差异标识；零值与缺失分开 |
| 长表和卡片 | 连续加载，保留显式加载更多；明细局部横滑而非整页横向溢出 |
| 动画 | 轻量过渡，支持减少动画；不在数据更新时突然改变卡片位置 |

应验证 360、390、430px 手机宽度及桌面布局。小屏仍能搜索 SKU、切换站点、展开依据和进入试算。登录、来源异常和空态也需适配，不只验收正常首页。

虚拟滚动仅在性能测量证明确有必要时引入，并验证展开高度、键盘操作和滚动恢复，不能为了无限下滑新增整套状态管理。

## 6 数据来源与权威口径

### 来源职责

| 数据域 | 优先来源 | 备用或补充 | 禁止行为 |
| --- | --- | --- | --- |
| 实际销售和历史成交 | 积加已核验经营接口 | 已确认 Excel 月报 | 同一站点周期同时累加两份来源 |
| 广告归因及投入 | 积加经营或广告接口，按指标确认 | 原始广告报表 | 把广告投入占比称为广告销售占比 |
| 退货和仓储 | 积加对应统计或明细 | 已确认月报 | 用缺失费项和缺失退货填零 |
| FBA 事实库存 | 积加 FBA 库存 | 带盘点日期的导入快照 | 把国内库存或采购单算成当前 FBA 可售 |
| 国内、在途和计划 | WPS 库存规划 | 已核验仓储或订单导出 | 把计划发货当已确认在途 |
| 采购成本和新品资料 | WPS 新品及现有产品成本 | 人工维护的有效覆盖值 | 用售价变化自动覆盖采购成本 |
| 订单与库存归属 | 真实采购、收发货和仓库记录 | 冠唐云导出或积加确有相应业务的数据 | 因接入积加而假设所有国内仓订单都在那里 |
| 试算费率 | 有来源和生效日期的配置 | 明确标记的人工确认值 | 把过去实收费用当作官方未来收费表 |

人工覆盖按字段保留，来源更新不能删除手工编辑、新品添加、采购已完成状态、发货备注或运营动作。WPS 与人工值冲突时展示差异并提供确认方式，不静默替换。

### 标准记录和追溯

扩展现有契约，不另建平行报告。每条经营记录至少保留：

- 来源、来源版本或运行编号、采集时间、业务截止时间。
- 店铺、站点、原始 SKU、标准 SKU、MSKU、ASIN 及映射状态。
- 经营周期、时区、币种、金额单位和字段完整性。
- 销售额、销量、均价、利润、广告、退货及仓储的值和来源口径。

库存记录另存盘点时间、仓库、批次、在途状态与预计到达；计划记录另存计划日期、订单编号和状态。不能共用一个更新时间冒充三类业务时间。

缺失值使用 null 和明确状态，真实零保留为零。新增接口数据不得沿用旧 Excel 解析中“空值即零”的简化处理。现有必填数值结构若不能表达未知值，应同步扩展契约与消费者并做兼容测试，不能只改页面显示。

API 未覆盖的字段继续引用最后有效的对应来源，并分别标明时间；不将混合来源全部标记为“积加最新”。新 SKU 即使无库存资料也可显示经营事实，不因缺少目录映射而整行丢弃。

### 匹配与去重

沿用现有 SKU 归一化和别名机制。去重键包含来源业务主键、店铺、站点、SKU 或 MSKU、期间，具体按接口粒度确认。

同一市场多个店铺或 MSKU 归属于同一 SKU 时，仅经确认后汇总；金额和件数可求和，百分比由汇总分子分母重算。不能按名称相似、去掉后缀或只按 ASIN 擅自合并。多义映射进入待处理清单。

共享国内库存单独记录所有权与适用站点，不能为 US、CA 各复制一份后再相加。汇总前需要检测来自 WPS 与 ERP 的同一批在途重复记录。

## 7 指标和比较规则

### 经营指标

| 指标 | 定义 | 约束 |
| --- | --- | --- |
| 销售额 | 已确认的商品销售金额口径 | 明确是否含优惠、退款、运费；同图只用一种定义 |
| 实际利润 | 与本站成本范围对账后的经营利润 | 未对账时显示来源利润或待确认，不冒充本站完整利润 |
| 利润率 | 已确认实际利润 ÷ 对应销售额 | 分母为零或缺失显示 — |
| 成交均价 | 与接口定义一致的销售金额 ÷ 对应成交件数，或确认后的接口均价 | 退货前后件数需一致；与当前刊登价分开 |
| 广告销售占比 | 广告归因销售额 ÷ 可比较的商品销售额 | 标明归因窗口；不同覆盖范围不强算 |
| 广告投入占比 | 广告花费 ÷ 对应商品销售额 | 与广告销售占比使用不同名称 |
| ACOS | 广告花费 ÷ 广告归因销售额 | 无有效分母显示 —，不能单独作为经营结论 |
| ROAS | 广告归因销售额 ÷ 广告花费 | 无有效分母显示 — |
| 退货率 | 已确认接口退货率，或明确口径的退货件数 ÷ 销售件数 | 同月退货可能属于早期订单，说明是否为订单队列口径 |
| 仓储费用 | 实际费用、所属期及覆盖项 | 区分月仓储、超龄等，不能把缺失费项当零 |

广告指标定义及 ACOS 与业务目标的关系参考 [Amazon Ads 官方说明](https://advertising.amazon.com/library/guides/acos-advertising-cost-of-sales)。经营判断仍需同时考虑利润与增长目标，不设置所有 SKU 共用的好坏 ACOS。

广告归因销售可能与经营收入存在归因窗口或退款处理差异。未经核验不得将“总销售额减广告销售额”直接称为自然销售额，不为了让占比小于 100% 强行截断原始数据。

站点汇总的销售额和利润按已确认记录求和，利润率由汇总利润除以对应销售额重算；广告销售占比、投入占比与退货率不能平均各 SKU 的百分比。某指标只覆盖部分 SKU 时显示覆盖范围，不用全站分母稀释问题。

总览库存覆盖优先显示“可计算 SKU 中达到三个月供应覆盖的比例”及当前 FBA 覆盖不足的 SKU 数，可展开口径与未能计算数量。不能用所有库存件数除以所有销量，制造慢销产品库存能补偿畅销产品缺货的错觉。

累计退货件数不得为了视觉合理而强行压到当期销量以内。无法核对订单队列时提供现有口径说明和有限分析，不宣称精准退货因果。

### 利润对账

接入时为每个利润字段登记包含和不包含的费用：采购、头程、佣金、配送、广告、退款、退货处理、仓储及其他费用。先用同一 SKU、站点、周期、币种的样本核验，再汇总。

积加 `salesNetProfit` 等字段作为候选来源利润，不未经对账直接映射成本站实际利润。已经被来源扣除的广告、退货和费用不得再次扣除。退款损失与退货率也不能重复算成本。

未拿到完整费用时可展示已确认销售额和部分费用，利润标记“费用未齐”或“来源利润待对账”，不自动得出亏损、盈利和盈亏平衡结论。

### 币种和时间

默认按站点原币展示：US 为 USD，CA 为 CAD，MX 为 MXN；实际接口币种必须逐条核验。积加枚举中的 YUAN 表示原币种，不表示人民币，详见 [积加常见问题](https://open.gerpgo.com/qa)。

汇率由配置或已确认来源提供，保留日期和方向；无汇率则不转换。跨市场汇总只有在用户主动选择统一币种且汇率覆盖完整时才可出现。

按店铺或市场业务时区定义日期边界，时区通过配置和接口事实确认，不以 NAS 中国时区替代美国业务日。展示区分采集时间、业务截止时间和报表期间。

### 库存覆盖

| 口径 | 计算方式 | 用途 |
| --- | --- | --- |
| 当前 FBA 可售覆盖 | 已确认 FBA 可售量 ÷ 参考日销 | 判断当前可售库存，不把 AWD 当成已上架 |
| 已确认供应覆盖 | 不重叠的 FBA、AWD 可用量和确认在途量 ÷ 参考日销 | 判断三个月目标库存及未来供货背景 |
| 国内及订单背景 | 国内实物、未完成采购、已发货、已入库分别显示 | 采购和发货判断，不直接并入海外可售覆盖 |

参考日销保留来源、窗口和算法。初始可比较最近三个完整月平均月销除以 30 与 WPS 参考月销，使用者确认后再用于计划；当前月不完整时不能直接当完整月。季节性、缺货和异常月份导致偏差时提示并允许保留人工计划值，不悄悄重写实际销量或 WPS 源表。

目标覆盖默认三个月，计算使用 90 天，配置可调整。发货建议基础量为 max(0, 目标需求量 − 已确认海外库存及在途量)，并受可发国内库存约束。显示取值依据和四舍五入或整箱调整，不叠加隐藏安全系数。

AWD 转 FBA 需要时间；确认在途需状态和预计到达日期。预测断货必须结合到达顺序与消耗，否则只展示供应覆盖，不声称精确断货日。零需求、缺历史或库存过期时显示无法计算，不显示无限覆盖或伪零天。

## 8 运营分析和建议

### 变化检测

优先比较同站点、同 SKU、同口径且完整的期间。排序考虑实际销售额或利润变化金额、持续时间及证据完整度，百分比仅作为补充，避免低基数 SKU 以大百分比占据全部注意力。

各类阈值、最低样本量、观察窗口和来源过期时间使用现有配置扩展。首批阈值通过历史回放及使用者确认后生效。试算默认广告 15%、退货 1% 不是经营警报线。

变化入口需覆盖：

- 销售额变化，并同时查看均价和件数，避免降价增量被解读为经营改善。
- 利润额及利润率变化，区分已核验成本变化与费用缺失。
- 广告销售依赖、广告投入和实际利润的联合变化。
- 退货、退款和仓储的持续变化及数据成熟度。
- 当前可售覆盖、在途到达和历史缺货造成的销售解释限制。

不得只用一个指标自动给出“加广告”“降价”“淘汰”等确定动作。低样本和费用不全的 SKU 优先建议核查数据。

### 单 SKU 建议格式

建议采用“发现 + 依据 + 下一步核查”的简短表达，展开后可查来源、月份和数值。

例如：“销售额连续两个月下降，成交均价基本稳定；建议核查流量和 FBA 可售状态。广告归因数据尚未覆盖完整月份，暂不建议据此削减预算。”这只是格式示例，不代表当前真实经营结论。

每条建议需要有可追溯的触发指标及周期，区分事实、解释可能性和建议。没有足够证据时明确写“待核查”，不生成看似肯定的原因。

### 未来三个月增长机会

将“增长机会”改为“增长机会待核查”，筛选具有连续历史、正向利润质量及供货支持的 SKU。查看最近三个月销售额与件数、成交价变化、广告投入效率、退货仓储、季节性和库存覆盖。

出现以下情况时不能仅凭销售增长推荐加大投入：明显降价、实际利润下降、依赖尚未成熟的广告归因、集中退货、即将缺货或成本未知。

提供增长支持证据、主要约束、下一步验证动作，不输出没有模型与事实支撑的未来收入预测。不使用不可解释的综合 AI 分数决定排序；历史不足时可以人工搜索，不强行进入机会清单。

### 季节性

至少有十二个完整且可比较月份才展示初步历史季节性，优先使用两个周期交叉核验。只有一个年度周期时仍标记有限证据，不能认定为稳定规律。

以销售额观察经营季节变化，同时校验件数和价格影响。沿用旧件数季节性时明确标为“历史件数规律”，不与销售额指数混用。缺货、广告突变及价格调整需要备注，历史规律不是未来增长承诺。

### 动作和复核

复用产品待办、协作和现有运行记录，不建立新任务系统。最小记录包括 SKU、站点、动作类型、日期、说明、基线数据版本、比较期和可选复核日期。

状态为待核查、处理中、待观察、已复核，具体复用现有状态字段或兼容扩展。修改建议或同步数据不能自动把业务动作标记完成。

复核展示动作前后可比较的销售额、利润及相关指标，保留同期价格、广告、库存和季节变化提示。只说明前后变化，不把相关性写成动作导致的收益。订单审核的“已完成”与运营动作的“已复核”不是同一种状态。

## 9 积加接入

### 鉴权和权限

复用服务端 `gerpgo.ts` 和现有数据更新接口。鉴权依据：[积加鉴权文档](https://open.gerpgo.com/document?id=596) 与 [积加常见问题](https://open.gerpgo.com/qa)。

- 环境配置沿用 GERPGO_APP_ID、GERPGO_APP_KEY、GERPGO_BASE_URL、GERPGO_SIGNING_ENABLED、GERPGO_TIMEOUT_MS。
- 官方基址为 https://open.gerpgo.com/api/open，不允许将密钥发送到任意配置域名或跟随重定向。
- 按官方约定申请令牌、携带 accessToken；启用签名时按实际发送 JSON 字节和 appKey 生成签名。
- 令牌仅在服务端内存使用，按照到期时间刷新，令牌过期最多触发一次重新鉴权后重试。
- NAS 实际公网出口加入积加白名单；局域网 IP、网站域名和 Cloudflare Tunnel 地址不是 API 出口白名单地址。
- 店铺检查通过仅证明本次基础访问，不代表广告、经营、库存等权限全部通过。
- 每个数据域登记权限、样本响应和可用期间。HTTP 200 还需校验业务状态，空数据不自动等于授权失败。

网页加密保存的完整凭证对优先于环境配置，不混合两种来源。解密失败需明确处理，不能静默换环境凭证访问另一个租户。

### 接口优先级

以下为候选接口与目标，正式字段绑定以当前官方文档和该租户实际授权响应核验为准，不代表均已开通。

| 优先级 | 数据 | 官方文档和候选接口 | 首批用途 |
| --- | --- | --- | --- |
| P0 | 店铺与市场 | [店铺](https://open.gerpgo.com/document?id=153)；/middle/base/market/page | 店铺、市场、币种和时区映射 |
| P0 | 产品资料 | [产品](https://open.gerpgo.com/document?id=53)；/purchase/goods/product/page | SKU、MSKU、ASIN 的映射 |
| P0 | 产品经营表现 | [产品表现](https://open.gerpgo.com/document?id=131)；/operation/sts/productAnalyzeMultiIndex/page | 月度销售、价格及已核验费用 |
| P0 | FBA 库存 | [FBA V2](https://open.gerpgo.com/document?id=5136)；/purchase/store/fbaInventory/page/V2 | 当前可售和库存状态 |
| P1 | 广告分析 | [广告](https://open.gerpgo.com/document?id=98)；/operation/ads/adsAsinAnalytical/page | 归因窗口与广告明细 |

| P2 | 采购单 | [采购](https://open.gerpgo.com/document?id=86)；/purchase/srm/procure/page | 租户确有对应订单时关联供应链 |

产品表现接口要求日期范围和 showCurrencyType，并按页取数；文档页大小上限为 100。金额字段可能同时带数值和币种，不能只取数值。示例中的 USD 不应硬编码到 CA 或 MX。

FBA V2 文档标为灰度能力，需要确认租户可用性；库存完整快照不得隐藏零库存 SKU。具体库存状态字段先采样确认，不能根据接口名称猜测可售量。

接口速率分别配置。产品表现文档的令牌桶容量 3 不等于每秒三次；FBA V2 文档的每秒两次也不能套用于所有接口。正式频率以生效文档、账户限制及限流响应为准。

### 首次同步

首次范围为已选择店铺、站点，最近六个完整月份及当月截至业务日期的经营记录，加当前 FBA 库存。授权允许且需求确认后再补十二至二十四个月，不能直接宣称完整季节性历史。

流程为：权限和店铺映射 → 小样本取数 → 字段与费用对账 → 全分页采集 → 预览差异 → 确认发布 → 页面验收 → 启用定时同步。

预览比较 API 与 Excel 在同站点、同月份的销售额、利润口径、SKU 数和关键费用，不相加。对已批准数据域和期间进行来源替换，其他域保留原来源。迁移前备份当前有效版本及数据库。

| 标准字段 | 积加候选字段 | 必须核验 |

| 商品销售额 | orderProductSales | 金额对象、币种、优惠与退款口径 |
| 成交件数 | orderProductAmount | 日期边界、取消与退货处理 |
| 历史成交均价 | averagePrice | 分子分母与期间 |
| 当前售价 | sellingPrice | 是否为当前刊登价、采样时间 |
| 广告归因销售额 | adsSales | 归因窗口与币种 |

## 10 WPS 接入和表格维护

### 授权方案

分享链接只用于识别和打开文档，不是稳定下载 API，也不代表 NAS 已获长期授权。

长期方式采用金山文档开放平台应用授权，在服务端保存受保护的授权信息，读取已批准文件，必要时导出为 XLSX，复用现有解析、预览和发布功能。依据：[个人文件授权下载流程](https://developer.kdocs.cn/server/example/personal-files.html)。

上线前确认应用审核、授权范围、文件归属、文档类型及 API 配额。个人文档、应用文档、WPS 表格和在线表格的能力不同，不能只凭分享页假设一种下载接口适用全部文件。依据：[金山文档接口说明](https://developer.kdocs.cn/server/guide/api.html)。

只读授权优先。不得导出 Mac 浏览器 Cookie、存储临时签名下载 URL、要求公开业务表格或将刷新令牌写入前端。授权过期时提示重新授权，维持最后有效数据。

在线文档需要转换时先确认是否为异步任务，按有上限的等待与重试检查结果，再取得实际 XLSX；不把任务提交成功当作文件已生成。

在正式授权完成前，手工下载并通过现有网页上传作为明确标记的临时方案，不称为自动同步。

### 库存规划

读取经过确认的库存、发货、采购相关工作表，保留文件、工作表、原始行和业务日期。全表扫描有效行，不能只读首表或前五项。

对重复表头、多层表头、合并单元格、SKU 空格和尾部空白做已定义的标准化。重复“在途”列按所在表头区域区分，不能将合计列与明细列重复累加。Walmart 等非本次站点范围的工作表不混入 Amazon 指标。

国内库存、工厂库存、未完成订单、在途与已到货分别确认；源表只提供合并数时保留合并口径，不凭空拆分。发货记录需要发货日期、SKU、数量、目的地和可用订单或批次标识。

参考月销是计划输入，不覆盖积加实际销量。网站可以生成带历史依据的建议值和对比预览，但本阶段不回写 WPS。需要更新源表时由使用者确认另行操作。

公式无缓存、结果错误、表头变更或字段缺失时阻止受影响域发布并给出具体位置。解析行数、有效记录数、唯一 SKU 数和跳过原因分别显示。

### 新品资料

新品未形成 SKU 时使用稳定候选产品标识，不能因缺少 SKU 丢弃。读取所有已确认工作表及有效产品，不限定前五个；数量对账按去重有效产品进行。

必要资料包括名称、可选 SKU、市场、Amazon 类目映射、采购成本及币种、单件包装尺寸和重量、外箱尺寸、装箱数、报价日期、调研说明及来源标识。

支持现有页面手工新增和编辑产品。人工覆盖与来源原值分别保留，下一次同步不能删除手工产品或覆盖尚未确认的编辑。文件新增、删除和改名要在预览中呈现；疑似标识变化不得自动删旧建新。

新增产品可直接进入利润试算，自动带入已确认资料，缺项再输入。当前还需提供新品文档及授权，不能保证仅凭库存文档获得新品成本。

### 更新检测

定时先检查授权文件版本或校验内容哈希，无变化则不重复发布；无法得到可靠版本时以完整下载后的内容哈希判断。

文件版本变化后只更新受影响数据域。WPS 版本时间不等于库存盘点时间，下载成功也不代表业务最新。临时下载链接仅在本次服务器任务中使用，并限制允许的来源及重定向目标，防止任意地址读取。

## 11 同步执行与自动调度

### 执行架构

推荐在现有应用镜像中增加独立同步执行入口，由 NAS Compose 启动同版本 worker 服务。worker 不开放公网端口，不启动第二个网页服务，不重复执行应用启动迁移，不挂载 Docker 控制接口。

网页只提交任务和读取状态，不在一次 HTTP 请求内执行长时间全量同步。扩展现有 /api/inventory/data-refresh 的动作和状态能力，并复用现有 SQLite 运行、异常、映射及业务记录。

积加请求继续使用现有 Node 服务端鉴权模块；标准化与报表任务沿用 Python store_ops jobs、CLI、StateDb 和 SKU 归一化机制。根据现有调用方式连接两者，不复制另一套 Python 鉴权、发布器或数据库。

worker 入口需随生产镜像打包，不能依赖 NAS 未安装的开发工具或 TypeScript 开发运行器。应用和 worker 使用同一个确定版本号，共享现有运营库及必要数据目录。

NAS 任务计划可作为替代方式调用同一同步入口；一个部署只启用一种调度所有者，避免 worker 和任务计划重复拉取。具体入口与配置变量在实施时加入现有配置，不在文档中伪装成已经存在的参数。

### 建议频率

以下是可配置默认建议，不是外部接口承诺。具体执行时段在业务时区、源数据更新规律和配额确认后确定。

| 数据域 | 建议频率 | 重拉范围 |
| --- | --- | --- |
| 销售及经营 | 每日 | 当月与上月，覆盖迟到与修订数据 |
| 当前 FBA | 每四小时 | 完整快照或经核验可正确处理删除的增量 |
| 广告与退货 | 每日 | 按实际归因和迟到窗口重拉 |
| 历史完整月份 | 首次补齐，之后定期复核 | 最近已结束月份优先，历史修订可手动重建 |
| WPS 库存与新品 | 每日检查版本 | 有变化才下载、解析和发布 |

首次允许手工运行，验证成功后再启用调度。暂停和频率变更需可见，服务重启后恢复已配置调度，不依赖网页有人打开。

### 分页与幂等

- 校验每页业务状态、结构和币种，取得全部页，不以第一页完成代替同步成功。
- 结合 total、页大小和实际响应结束条件，检测提前空页、重复页、页数异常和重复主键。
- 避免接口分页期间数据变化造成漏取；按接口能力分割稳定日期窗口，并以重叠窗口复核去重。
- 为来源、店铺、数据域、期间和请求范围建立幂等标识；同一任务重复执行不重复累加。
- 游标只有在相应范围完成校验并发布后才推进。分页检查点可以用于恢复，但不能把未发布进度当成功。
- 单一有效发布者；数据库锁带租约与恢复机制，进程崩溃后可安全接管，不能永远锁死。
- 全量快照需识别记录删除；增量无可靠删除语义时定期重拉全量，避免永久保留已失效库存。

### 错误和重试

超时、连接异常、服务端临时错误和限流使用有上限的指数退避与随机抖动，并尊重可用的 Retry-After；建议同一请求最多五次尝试，包含首次。

凭证错误、白名单错误、字段结构变更、明确权限失败不无限重试。权限独立登记，缺广告权限不阻止已经核验的销售数据使用，但必须说明缺失域。

某个域或期间未完整拉取时，不发布该域或期间。可将其他独立核验完成的数据与旧版本未更新域组成新版本，但标为部分更新，逐域显示时间，不能显示全站同步成功。

## 12 发布、缓存和恢复

### 发布流程

沿用现有标准报告和上传发布逻辑，补齐整批一致性：

1. 在暂存版本目录保存经过脱敏的原始样本和完整标准数据。
2. 校验契约、主键、分页完整度、来源、金额单位及期间。
3. 对账 SKU 数、销售额与关键费用，输出新增、删除和差异预览。
4. 在同一文件系统生成不可变报告版本及 manifest。
5. 校验通过后原子切换当前版本指针。
6. 更新运行记录、发布信息和已完成游标。
7. 页面按新版本读取，保留上一有效版本用于恢复。

第一次替换来源、结构变更和异常大幅波动需人工确认。已批准规则下的日常更新可自动发布；新的未知字段或站点不能因旧规则批准而自动接受。

不得逐个覆盖多个线上报告后才发现中途失败。数据库与文件系统不是天然同一事务，应区分准备、发布和完成状态，重启时核对 manifest 与数据库，修复“指针已切换但记录未完成”等中断情形。

### 页面读取

一次页面请求捕获同一版本标识，跨经营、库存和目录文件读取同一组 manifest，避免出现不同代报告混合。每个数据域仍有自己的业务日期。

缓存键包含版本标识与内容标识，不能仅依赖文件大小和修改时间。版本改变后重新读取；格式不兼容、文件缺失等需记录具体异常。

最后有效版本可用于故障展示，但必须注明旧版本及原因，不能静默成功。某个辅助来源失败不应令整个 SKU 页面因对 undefined 调用 filter 而崩溃；缺集合的兼容降级需显式记录，不吞掉真实错误。

### 回退和留存

回退以完整报告版本为单位，覆盖本版新增或移除的文件关系，不仅恢复单个 JSON。回退报表不回退独立人工编辑、订单状态和后续动作记录，二者影响需说明。

建议保留最近十个成功版本及三十天必要采集资料，数量与期限可配置，并设置容量告警。保留资料先脱敏，不包含凭证或不必要的客户信息。清理当前版本或唯一备份前必须阻止执行。

备份包括现有账号库、运营库、人工覆盖、报告版本、来源配置及配套 SECRET_KEY；备份存放和加密要求与实际部署环境一致。迁移后从预览和只读检查开始，不直接覆盖已有 NAS 数据。

## 13 利润试算

### 使用目标

独立页面尽可能少填。默认 US、广告占销售额 15%、退货情景比例 1%、税费 0；默认值允许调整并明确标为估算假设，不用于真实经营分析阈值。

基本流程：选择市场 → 选择 Amazon 类目 → 选择现有 SKU、新品或手工产品 → 自动带入有效资料 → 补齐必要输入 → 查看结果。

市场和类目只是匹配入口。FBA 配送还需要单件包装尺寸与重量；头程还需要外箱、装箱数及线路。不能承诺仅选类目即可自动得到全部费用。

### 自动匹配和手工覆盖

| 项目 | 自动来源 | 缺失或不适用处理 |
| --- | --- | --- |
| 成本和币种 | 产品成本、新品资料、已确认覆盖 | 提示输入，不用零成本 |
| 单件包装和重量 | WPS 或产品目录 | 缺资料不自动计算 FBA |
| 外箱和装箱数 | WPS 或人工确认 | 缺资料不自动计算头程 |
| 佣金 | 市场和已确认 Amazon 类目费率 | 无配置显示待确认 |
| FBA 配送 | 市场、适用规则、包装和重量档位 | 超范围或无档位提示手动确认 |
| 头程 | 所选市场的预设线路和计费规则 | 显示币种、单位和适用范围 |
| 汇率 | 有日期的有效配置 | 无汇率不能混币计算 |

沿用 STORE_OPS_PROFIT_FEE_RULES 及现有费率校验能力，优先扩展有效日期、来源与适用范围，不新建另一套费率系统。当前默认配置为空，不宣称已经预装官方收费表。

内部类目需映射到 Amazon 佣金类目，经确认才可使用。配置中若存在最低佣金、价格区间或附加收费，必须支持其实际公式或标明当前不适用，不能套统一百分比。

市场变更后重新匹配币种、费用和类目；不跨站点保留不明确的售价与费用覆盖。手工覆盖保留原来源值及覆盖提示。

### 计算规则

所有成本先转换为同一市场币种，保留汇率日期。非负成本、正数装箱量、有效尺寸重量及比例范围均校验，非法输入不生成结果。按当前体积线路，单件头程为：

外箱长 cm × 宽 cm × 高 cm ÷ 1,000,000 × 每立方米费用 ÷ 装箱件数。

这一公式仅适用于体积计费线路。计费重、最低收费、混装分摊和附加费尚未支持时明确提示，不自动使用体积公式代替。

预估单件利润为售价减去采购成本、头程、佣金、FBA 配送、广告估算、退货损失估算及明确输入的其他成本；利润率为单件利润除以售价。

初版可将退货损失预算设为售价乘 1%，但必须写明它是简化情景，不是按真实订单退货率精确还原的损失；用户采用退款及残值模型时，应替换该预算而非再扣一次。

输出预估利润、利润率和简洁费用构成。盈亏平衡售价仅在费用范围完整且适用公式可正确求解时显示；阶梯费用或最低收费不支持时提示，不给伪精确结果。

缺任何必要成本或费率时不输出完整利润结论，可以显示已输入的费用小计。涉及税、危险品、电池专项规则的商品提示不在本次适用范围。仓储和未计入附加费列出，不隐藏在“最终利润”中。

## 14 库存和供应链后台

### 库存展示

保留 SKU 筛选和无限下滑，季节库存放在库存视图内部，不另设前台入口。库存、采购和发货页面用分段库存条、流向或到达时间展示 FBA、AWD、在途、国内和采购，而不是只展示数字。

每段显示实物或计划属性、来源日期和数量。海外目标三个月覆盖只使用经过核验且不重复的库存及在途；订单和国内库存作为可调度背景，不混入已经可售的库存。

历史发货明细至少能按 SKU 查看日期、数量、目的市场、订单或批次及状态。原始文件没有某字段时显示缺失，不创建推测发货记录。

### 订单归属和库存组成

供应链页面需回答：某次出库的 SKU 属于哪些采购订单；当前某 SKU 的仓内库存由哪些订单或批次组成；历史采购如何转化为收货、出库、在途和当前结余。

必要数据包括采购订单行、SKU、订购量、状态，入库行与订单关联，出库行与订单或批次分配，以及期初库存、调整、退货和盘点差异。只有主表累计库存时无法证明订单构成，应明确标记待补数据。

优先使用真实关联。一次出库可分配多个订单，同一订单可多次出入库，已分配总量不得超过对应有效库存。库存组成总量必须与仓库结余核对；有差异进入异常清单。

缺实际关联时可提出 FIFO 推算方案，但必须有完整期初、连续出入库和调整记录，使用者确认后启用，并始终标为推算而非事实。数据不完整时不自动分配。

冠唐云数据可用授权导出的主表和明细作为初期只读导入来源，不假设其公开 API 已可调用；后续接口以实际产品版本、供应商文档与授权为准。详细扩展沿用 [仓库与供应链需求](guantang-wms/README.md)，发生冲突时以前台范围及本文件账号口径为准。

### 历史状态保留

以前标记已完成的采购任务不得因同步重新变成待采购。新导入状态与人工状态冲突时提供审核，不能再次批量把所有早期任务无条件完成。

不因订单主表缺失而删除已保存的发货历史。可用原始标识保留记录并进入待映射清单，避免 SKU 详情显示空白或整页异常。

## 15 安全和部署

### 凭证保护

沿用现有 AES-256-GCM 加密保存和 SECRET_KEY 派生方案；运营库中不得保存明文 appKey。加密密钥与数据库配套备份，更新镜像不随意更换 SECRET_KEY。

网页不回显 Key，不写浏览器本地存储；提交后清空输入。接口、运行记录、异常、报告和备份索引不含明文密钥、令牌或带凭证 URL。日志记录安全的错误类型与运行编号。

表格及第三方响应视为不可信业务数据，只解析批准字段，不执行宏、外部链接或文档中的指令。下载和上传沿用现有文件校验，限制文件体积、解压体积及处理时长，遇到超限明确失败。

WPS 授权、刷新凭证若需持久化，沿用现有加密配置能力进行最小扩展，并进行有效期、撤销和解密失败验证，不额外实现不兼容的明文配置文件。

### NAS 配置

真实部署以 NAS 当前项目的有效 Compose 和数据卷为准，不用本地示例目录覆盖现有目录。保留现有账号库、operations_data、runtime_output 和来源数据挂载关系，不能为了让服务启动新建空数据库替代旧库。

环境文件模式需要在有效 Compose 的应用环境中映射 GERPGO 参数；只向 .env 增加文本不足以传入容器。重新创建应用服务才会应用环境变更。网页加密保存模式不要求这些凭证环境映射。

新增 worker 共享现有运营库及报告版本目录。当前报告挂载存在只读约束，实施时给发布者提供准确范围的写权限，网页可保持读报告；不得全盘提权或递归开放 NAS 目录。现有上传任务仍需写入时也必须明确授予所需范围，不能造成旧上传功能失效。

NAS 管理界面可能保存独立的项目配置。文件修改后应核对界面实际 Compose、容器环境与数据挂载，不能仅看侧载文件就认定已经生效。Key 核对只显示是否配置，不能输出真实值。

应用健康检查与同步 worker 心跳分开。应用可访问不表示同步成功，worker 停止不应令已有经营页面不可读。Cloudflare 负责入站访问，不替代 API 出站连接或 IP 白名单配置。

### 发布与迁移

每次实施发布使用可追溯版本号，应用和 worker 固定同一版本。沿用当前 GitHub 镜像流程，验收 NAS 架构对应镜像存在后再给出更新说明，不只创建不存在的标签。

本需求不执行镜像发布。后续发布需给出匹配现有目录和卷的 Compose 增量变更、无秘密的 env 模板、迁移备份和回退说明，真实 Key 由使用者在 HTTPS 页面或 NAS 环境文件填写。

## 16 实施顺序

| 阶段 | 工作 | 通过条件 |
| --- | --- | --- |
| 第一阶段 接入验证 | 核对有效 NAS 配置、真实授权、店铺和市场映射、接口权限、费用及币种 | 能说明每个域是否可用，样本与原来源对账完成 |
| 第二阶段 手动闭环 | 全分页拉取六个月、标准化、差异预览、整批发布、页面版本和真实状态 | 手工一次更新完整可查，失败不损坏旧版本 |
| 第三阶段 自动运行 | 同镜像 worker、队列、调度、锁、重试、恢复、缓存、备份 | NAS 无 SSH 情况可管理，重启及失败恢复验证通过 |
| 第四阶段 运营完善 | 广告退货仓储、真实筛选、证据卡片、动作复核、WPS 授权与新品联动 | 依据完整、缺失透明、页面和试算可实用 |
| 第五阶段 供应链补齐 | 主表与明细导入、订单出库关联、当前库存构成、差异处理 | 可追溯真实订单，推算与事实分开，总量对账 |

WPS 接入可在第三、第四阶段并行准备，但无授权时不阻断已经独立验收的积加域。页面布局在第二阶段结合数据契约逐步优化，不等待所有接口完成才调整，也不先做无法支撑的数据图表。

优先复用现有配置和接口，再扩展 jobs、契约及必要组件。各阶段单独验证与发布，不以一次大重构同时替换所有模块。

## 17 验收标准

### 接入与数据

| 编号 | 场景 | 通过标准 |

实施代码后执行对应 lint、typecheck、单元及集成测试、生产构建和启动检查。涉及同步、发布、凭证和仓库的流程需故障注入及独立测试库；不得指向生产数据库做破坏性验证。

性能在首批实际样本规模下记录基线。普通查询不触发外部实时全量采集；卡片只加载当前批次，后台长表分页或游标取数但前台不展示页码。发现大数据性能问题后再做有证据的最小优化。
