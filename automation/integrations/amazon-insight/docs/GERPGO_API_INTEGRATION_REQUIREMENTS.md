## 0. 当前实施口径（2026-10-07）

本节覆盖旧章节的父体展示、角色分级、前台供应链和 PDF 要求。下方历史接口清单继续作为接入参考，不能作为已完成功能清单。

当前授权入口在既有“数据更新”页面：服务端读取 `GERPGO_APP_ID` / `GERPGO_APP_KEY`，调用鉴权接口后只读检查店铺接口（153，`page=1,pagesize=1,condition={}`）。复用 `/api/inventory/data-refresh` 的 `test_gerpgo` 操作和 SQLite 运行/异常表；不返回凭证、令牌或店铺原始记录，不发布或重建报告。连接测试代码完成不等于 NAS 实际授权成功，仍需配置出口 IP 白名单并用真实凭证测试；销售/广告/库存等权限未逐项验证。业务分页拉取、转换和定时同步尚未实施。

`v1.3.10` 新增同页 appId/appKey 输入，用既有 API 的 `save_gerpgo_credentials` 操作保存；不新建页面或 API。HTTPS、同源 Origin、有效登录与 JSON 请求均需满足。完整凭证对用 AES-256-GCM 和 NAS 现有 32 字符以上 `SECRET_KEY` 加密后存入现有运营库，更新容器后保留。网页保存优先，未保存时才用环境变量；无法解密时明确报错，不静默回退。密钥提交后清空、不回显，不保存至浏览器、镜像、日志或 Git。运营库和 SECRET_KEY 必须配套备份；共用账号所有可信使用者均可修改配置。

### 0.1 页面安排

最终部署版本为 `v1.3.11`，相较 v1.3.10 新增浏览器发送前的 HTTPS 检查，误用 NAS HTTP 地址时不发送密钥；仅本机回环测试允许 HTTP。

- 所有人使用同一登录账号和工作区，仍校验有效登录，不按管理员/成员限制功能。凭证、原始 API 响应和授权令牌始终只在服务端保存，不能因共用账号而发给浏览器。
- 主页面仅运营总览、SKU 经营简报、利润试算；库存/采购/发货/供应链/新品资料/导入历史留在折叠业务后台。
- 经营展示不使用父体分组、排行或筛选。总览无“五条建议”，默认不铺产品卡片，搜索后最多预览三张；简报每张是一个站点下的 SKU，简短建议和展开依据共处一张卡。
- 无 PDF 功能。浅灰与白色层级、系统字体、蓝色操作、清晰留白；桌面浅色侧栏，手机底部三个主入口。没有另建演示站点。

### 0.2 数据所有权与落点

继续使用现有标准报告和 SQLite 工作区，不创建第二套业务数据库。

| 数据域 | 首选来源 | 标准落点/消费位置 | 不允许的替代 |
| --- | --- | --- | --- |
| 经营金额与均价 | 积加产品表现（131） | `profitability.json` → 总览/经营卡片 | 不用 WPS 件数、货值或标价推算销售额 |
| 广告销售/花费、退货与仓储 | 积加产品表现，必要时相应明细接口 | 同一 SKU/周期经营事实，细节后台 | 广告花费比例不等于广告销售比例；退货不等于退款 |
| FBA 可售/不可售/预留 | 积加库存接口，授权后实测 | 现有 `inventory_dashboard*.json` 的明确字段 | 库存总量不等于可售，下载日期不等于库存日期 |
| AWD / AWD转运 | 可核实接口，否则独立来源 | 保留来源和日期的库存字段 | 不从 FBA 在途或 WPS “AWD备货”猜测 AWD 实存 |
| 国内现货/采购订单/实际发货/在途 | WPS 库存规划；有正式仓库台账后优先台账事实 | 现有库存、单据和供应链模型 | “工厂库存及已下订单”是合计，不能直接拆成现货和订单 |
| 参考月销/覆盖目标/计划 | WPS 库存规划与现有人工覆盖配置 | 规划参数、采购/发货后台 | 不能覆盖实际销量、不能自动把计划改为执行单 |
| 新品成本/箱规/单件包装 | WPS 新品表，积加产品接口可补已建档产品 | `new_product_research.json` / 现有产品目录 → 试算 | 采购价 RMB 不直接当 USD，外箱不代替单件包装 |
| 佣金/配送/头程规则 | 经确认的市场/类目/线路/日期配置 | `STORE_OPS_PROFIT_FEE_RULES` → 试算 | 积加历史实付费用不是 Amazon 新品费率表 |

WPS 库存表现有“库存规划”“加拿大库存计划 ”、“价格维护”“Walmart ”等工作表；只映射批准的工作表，兼容尾随空格。不把 Walmart 数据混入 Amazon。源表大量 CM 历史列和末尾同名在途列须按所属区块识别：历史发货与当前在途不能因名称相同而重复累计，也不能把首次出现列当作唯一权威。

### 0.3 粒度、时期和口径

采集键为 `(source, storeId/marketId, market, sku, msku, businessDate/period)`，MSKU/ASIN 仅作匹配证据；保存原始 SKU 与标准 SKU。父 ASIN/SPU 可留在源记录，但不用于前台展示/汇总。

现有前台的 `(market, sku, period)` 是输出粒度。接入前先核实一个 SKU 是否跨店铺/MSKU：多 MSKU 确认可合并后才加总收入/花费/件数；平均价和比率用合计分子分母重算，不相加百分比。若现有结构不能区分店铺且映射不唯一，记录异常并阻止受影响记录发布，不取第一页或第一条覆盖。

- 销售事实按业务日期及站点时区整理为完整月份；当月标记“截至日期”，不与整月环比直接比较。拉取完成时间、业务日期、库存快照日期分别记录。
- 币种按来源原币种，US/CA/MX 不跨币相加。退款/退货、当前售价/成交均价、广告归因周期分开命名。
- `orderProductSales` 对应销售额；`averagePrice` 对应成交均价；`sellingPrice` 对应当前售价；`adsSales` / `adsSpend` 分别为广告销售/投入；`storageFee` 为仓储。广告总数和产品表现来源不重复累加。
- `salesNetProfit` 的成本、广告、仓储、退款包含关系须和现有实际利润公式对账后才能映射 `actualProfit`；对账前不猜净利润，也不重复扣广告/仓储。确认需要独立口径时只扩展现有报告字段并加兼容测试。
- Excel 与积加同一周期按已批准来源切换，不相加。无历史月份就显示缺失；WPS 季节性件数可补趋势，不补造金额/历史售价。
- 库存覆盖目标为 90 天：只合计无重叠的 FBA 可售、AWD 可用、真实在途等已确认桶；国内现货和未完工采购不进入海外三个月可售覆盖。必须先确认 AWD 转运与 FBA 在途是否重叠，未确认数量不双计。不同源日期明显错开时提示，不给精确发货结论。
- 国内库存按仓库/SKU 是全局池，分配到 US/CA 的订单单独记录，不能从两个站点表把同一国内库存加两次。取消/完成采购任务的人工审核及手动覆盖继续保留，并清楚标记覆盖值与原始值。

### 0.4 WPS 访问与同步方案

2026-10-07 已验证用户提供库存分享文档可预览；经用户明确确认页面账号登录后下载成功。现有解析器识别五个工作表，源文件保存在 runtime 待发布批次，不修改云端源表。新品链接和字段结构尚待提供。

官方能力依据：[个人文件授权下载](https://developer.kdocs.cn/server/example/personal-files.html)、[接口类型说明](https://developer.kdocs.cn/server/guide/api.html)。分享可预览不是开放 API 授权；不能把 `/l/...` 返回的网页当作工作簿。

1. 首选服务器 OAuth：应用审核后按官方流程授权，服务端保存应用密钥、访问/刷新令牌；通过授权文档 ID 获取下载地址。在线表格必要时转换成 XLSX 并查询任务结果，WPS 表格可直接下载或读取授权选区。可用范围、配额和格式须在实际账号验证。
2. 浏览器下载作为当前过渡入口：会话有效且有权限时访问文档，下载只读副本，交给现有导入器。它是当前电脑上的交互下载，不承诺无人值守或 NAS 复用。无需用户公开表格、交付密码或浏览器 Cookie。
3. 无授权/无下载权限时保留上次数据并提示“需要重新授权/无下载权限”；不能绕过登录、自动扩大分享权限或将页面截图 OCR 当成完整台账。

环境配置已有两个源文档入口 `STORE_OPS_WPS_INVENTORY_URL` / `STORE_OPS_WPS_RESEARCH_URL`。这两个值只启用“打开源文档”，不启用定时同步。实际连接配置届时沿用现有配置/secret 系统，下载 URL 短期获取，日志不得包含签名参数、Cookie 或令牌。

### 0.5 同步、版本与页面更新

```text
积加授权 API / WPS 授权下载
  → runtime 原始只读快照 + 来源版本/散列 + SQLite 运行/异常记录
  → 已有解析器与 SKU/站点映射 → 导入预览、对账与完整性检查
  → 同一批报告一致发布（失败回滚，旧快照继续可读）
  → 已有加载层重新读取 → 总览 / SKU 卡片 / 利润试算 / 后台
```

拟采用每日定时同步和后台手动触发，频率在配置中调整，首轮授权/映射/结果需人工确认。积加首次导入尽量补足历史 12–24 月，实际可用范围以账号权限及接口实测为准；以后重拉最近重叠窗口，处理退款和迟到数据。WPS 比较版本/散列，无变化不发布，有变化只重建受影响的数据域；不把库存更新误当销售月份更新。

自动发布必须在固定映射确认后启用：下载完整、全部分页成功、必需列/单位/日期完整、无冲突 SKU、金额对账通过。全表空白、缺工作表、数据行数突变、公式没有缓存值、无法确认盘点日期均需复核，不覆盖成功快照。空白、零、公式错误分别处理。批次锁避免并发，幂等键避免重复导入。保留最近成功版本供恢复，不在网页请求期间同步外部服务。

现有发布链路还没有跨多报告的完整事务/失败回滚保证；正式接入前必须修补并测试，不能直接把当前 `publish_batch` 放入无人值守自动发布。复用现有导入批次、报告 schema 和操作日志，不新增平行导入 API 或调度系统。

数据更新页后续显示每域：连接状态、最后尝试/成功时间、业务截至日期、源版本、匹配/失败行数、待发布批次、错误原因和重试入口。现阶段只显示真实“尚未接入”和已配置分享入口；不得仅因有环境变量、HTTP 200 或下载成功就标记业务同步成功。

### 0.6 新品自动带入与接入验收

新品 WPS 表至少需稳定候选 ID/SKU、名称、市场、佣金类目或待映射内部类目、成本及币种、单件包装长宽高 cm/毛重 g、外箱长宽高 cm/件数；可选建议售价、供应商、备注。缺项保留可编辑，不造默认成本。计算器仍默认 US、广告 15%、退货 1%、税 0%，不含危险品/电池。选站点/类目后匹配已确认费率；有资料则带入，剩余只填缺项。

验收按三个阶段：

- 已实施：共用登录；浅色主界面；无父体及五建议；按 SKU 搜索与依据展开；来源入口配置；现有 Excel 路径可读。
- 授权后实现：积加鉴权、完整分页、字段转换/对账；WPS OAuth/文件下载；运行日志和回滚；首次完整数据预览。没有凭证不做假连接。
- 数据验收后启用：NAS 定时作业、失败恢复、数据新鲜度、移动端实际数据检查、无需人工上传的定时更新。定时同步程序不依赖 Codex 会话持续在线。

## 1. 背景与目标

当前系统主要通过 Excel 文件导入库存、销售、广告、采购、发货和利润数据。该方式可以作为兜底，但存在数据滞后、人工下载重复、来源时间不一致和 SKU 综合判断成本高的问题。

本需求将积加开放平台作为新的运营数据入口，在不重做现有系统的前提下：

1. 通过服务端定时或手动同步积加数据。
2. 将外部数据转换成项目现有的库存、利润、广告、采购和经营简报数据结构。
3. 保留 Excel 上传作为补充和故障兜底，不让页面直接依赖外部 API。
4. 前台聚焦运营总览、单 SKU 经营简报和新品利润计算器；供应链、库存调整、采购操作、发货操作和同步记录等进入共用账号的业务后台。
5. 所有经营结论都能追溯到数据来源、统计周期和计算口径。

## 2. 范围

### 2.1 本期范围

- 美国站和加拿大站；墨西哥站预留数据结构，暂不作为首期验收范围。
- 店铺、产品、销售表现、广告、退货、FBA 库存、采购订单、仓库出入库和月度仓储费同步。
- 建立采购订单、入库批次、出库批次和当前仓库库存之间的可追溯关系。
- 首次全量同步、定时增量同步、管理员手动同步和失败重试。
- 数据新鲜度、同步日志、异常记录、API/Excel 来源标识。
- 将同步结果写入现有标准 JSON、SQLite 状态库和现有页面读取链路。

### 2.2 不在本期范围

- 向积加写入采购单、调拨单、广告设置或产品资料。
- 同步买家姓名、邮箱、地址等个人信息。
- 用积加 API 替换新品利润计算器的佣金和 FBA 配送费规则表。
- 在浏览器中直接调用积加 API。
- 首期新增消息队列、Dagster、n8n 等编排系统。

## 3. 已确认的开放平台规则

以下内容已从积加开放平台公开文档确认：

- 完整请求地址为 `https://open.gerpgo.com/api/open/{url}`，其中 `{url}` 使用接口文档中的请求地址。
- 未配置 IP 白名单时默认禁止访问。白名单支持单个公网 IP、IP 范围、CIDR 和通配符；生产环境不得使用 `*.*.*.*`。
- `appId` 和 `appKey` 由开放平台账户获取。
- `POST /api/open/api_token` 使用 `appId`、`appKey` 换取 `accessToken`；Token 有效期为 86400 秒。
- 业务接口通过请求头 `accessToken` 传递令牌。
- 生产环境建议开启签名：对“实际发送且不含换行的 JSON 原文 + appKey”计算 32 位小写 MD5，并通过请求头 `sign` 传递。签名原文与 HTTP body 必须逐字符一致。
- 接口采用独立桶限流；不同接口的容量和速率不同，客户端必须按接口分别限速。

官方依据：

- [获取 accessToken](https://open.gerpgo.com/document?id=596)
- [开放平台 Q&A：访问凭证、白名单、签名和接口调用](https://open.gerpgo.com/qa)

## 4. 用户与权限

| 角色 | 能力 |
| --- | --- |
| 管理员 | 查看接入状态；测试连接；发起同步；查看同步日志和异常；管理字段映射；执行 Excel 兜底导入；恢复历史数据版本 |
| 普通成员 | 查看运营总览、经营简报、只读供应链追溯和新品利润计算器；不得查看凭证、原始响应、后台同步入口或修改采购/库存数据 |
| 系统任务 | 读取 Docker secret/环境变量；调用积加 API；写入运行目录和状态库；不得拥有积加写接口权限 |

当前已取消角色分级，以上历史角色表不再作为本期权限要求。所有同步入口必须校验共用账号的有效会话；凭证/令牌继续仅服务端可见。

## 5. 总体流程

```text
NAS 定时任务 / 管理员手动触发
            ↓
积加 API 适配器（鉴权、签名、限流、分页、重试）
            ↓
原始快照（短期留存） + 同步游标 + 运行/异常记录
            ↓
字段标准化与 SKU/站点映射
            ↓
现有标准报告 JSON / SQLite 覆盖与审计数据
            ↓
现有 Next.js 数据加载层
            ↓
运营总览 / SKU 经营卡片 / 供应链追溯 / 管理员后台
```

约束：页面只读取本地标准化快照。积加接口失败时继续提供最近一次成功快照，并明确显示数据时间和失败状态。

## 6. 接口范围与用途

### 6.1 首期接口清单

| 优先级 | 数据域 | 接口 | 已确认限制 | 项目用途 |
| --- | --- | --- | --- | --- |
| P0 | 鉴权 | `POST /api_token` | 10 次/秒；Token 24 小时 | 获取和刷新访问令牌 |
| P0 | 店铺 | `POST /middle/base/market/page` | 1 次/秒；最多 100 条/页 | 建立店铺、站点、`marketId` 映射 |

## 7. 数据映射要求

### 7.1 核心映射

| 积加字段/接口 | 目标字段或用途 | 规则 |
| --- | --- | --- |
| `marketId`、店铺/站点信息 | `market`、店铺映射表 | 由管理员确认 US/CA，不在代码中硬编码 ID |
| 产品 `sku`、`mskuList`、`spu` | 产品目录、变体目录 | SKU 转大写并沿用现有标准化规则；原始值保留 |
| 产品 `packageL/W/H`、`packageWeight` | 箱规/包装资料 | 单位必须通过租户实测确认后入库 |
| 产品表现 `orderProductSales` | SKU 月销售额 | 作为前台主指标；使用接口返回币种 |
| 产品表现 `averagePrice`、`sellingPrice` | 历史均价/当前售价 | 按市场、SKU、月份保存，页面展示趋势而非只保留最新值 |
| 产品表现 `adsSales`、`adsSpend` | 广告销售额、广告花费 | 广告销售占比 = `adsSales / orderProductSales` |
| 产品表现 `returnsRate`、`refundsRate` | 退货/退款风险 | 与退货订单明细交叉校验，不混为同一指标 |
| 产品表现 `storageFee` | 仓储成本 | 月度仓储费接口为核对源；冲突时记录异常 |
| 产品表现 `salesGrossProfit`、`salesNetProfit` | 毛利、实际利润 | 保留接口币种和统计周期，不跨币种直接相加 |
| FBA V2 `afnFulfillableQuantity` | `fbaSellable` | 站点和仓库映射确认后写入 |
| FBA V2 `inTransitQty`、`inboundTotal` | 在途库存 | 两者定义不同，禁止直接相加；联调后确定本站主口径 |
| FBA V2 库龄字段 | 库龄分布、滞销风险 | 0–30 天至 365+ 天完整保存 |
| FBA V2 `unitsOrdered*`、`avgUnitsOrdered*` | 近期销量与周转 | 用作库存短周期判断，不替代长期月度历史 |
| 采购单号、状态、SKU 数量 | `pendingOrders` | 仅计入未完成且剩余量大于 0 的订单 |
| 采购单/交货单与入库明细 | 仓库库存订单构成 | 优先使用远端直接关联；不得仅凭采购日期认定当前库存归属 |
| 出库单/发货批次与出库明细 | 出库 SKU 订单归属 | 支持一个出库 SKU 拆分消耗多张采购订单 |
| 仓储费 `storageFee`、`monthOfCharge` | `storageCost` | 按市场、SKU、月份汇总 |

### 7.2 主键与去重

- 店铺：积加店铺/卖家编码 + `marketId`。
- 产品：标准化 SKU；MSKU、ASIN、FNSKU 作为映射键，不替代内部 SKU。
- 月度经营表现：市场 + SKU + `YYYY-MM`。
- 日广告：市场 + ASIN/MSKU + 日期。
- 订单/退货/采购：使用远端单据 ID；明细追加行号或远端明细 ID。
- 库存快照：市场 + 仓库 + SKU + 快照时间。
- 入库事件：仓库 + 入库单/批次 + SKU + 明细 ID。
- 出库事件：仓库 + 出库单/发货批次 + SKU + 明细 ID。
- 出库分配：出库明细 + 来源入库批次/采购订单；同一出库明细允许多条分配。
- 同一请求重跑必须幂等；不得生成重复月份、重复订单或重复费用。

### 7.3 来源优先级

1. 积加 API：销售、广告、FBA 库存、退货、仓储费、采购状态的默认事实源。
2. 管理员确认的手工覆盖：用于修正映射或补充积加缺失字段，必须保存修改人、时间和原因。
3. Excel 导入：API 未覆盖的数据和故障兜底。
4. 计算值：基于上述事实源生成，必须记录公式版本。

同一字段发生冲突时不静默覆盖：保留原始值，在后台生成数据质量异常，并显示当前采用的来源。

## 8. 同步需求

### 8.1 同步模式

| 模式 | 范围 | 建议频率 |
| --- | --- | --- |
| 首次全量 | 店铺、产品、最近 24 个完整月经营表现、最近 24 个月仓储费、当前库存、未完成采购单 | 接入时一次 |
| 库存增量 | FBA 当前库存、在途、预留、库龄、近期销量 | 每 4 小时 |
| 经营增量 | 当月和上月产品表现、退货、订单核对 | 每日 02:30 |
| 广告增量 | 最近 3 天逐日重拉 | 每日 03:30 |
| 采购增量 | 未完成采购单及最近更新时间 | 每 6 小时 |
| 月度结账 | 最近 2 个完整月经营表现和仓储费重拉 | 每月 5 日和 10 日 |
| 手动同步 | 管理员选择市场、数据域和时间范围 | 按需 |

首期不在应用容器内增加常驻调度器。实现可重复执行的 `sync-gerpgo` CLI，由 NAS 任务计划调用；管理员后台复用同一服务端任务入口。

### 8.2 Token、限流和分页

- Token 缓存在服务端内存或运行目录，不写入前端，不进入标准报告。
- Token 距离过期少于 30 分钟时主动刷新；遇到明确的 Token 失效响应时仅刷新一次并重试原请求。
- 每个接口使用独立限流器，实际速率不超过文档上限的 70%。
- 分页始终显式传入 `page/pagesize` 或接口规定的 `pageInfo`，直到返回行数小于页大小或达到 `total`。
- 单次任务设置最大页数保护；达到保护值时任务失败并记录异常，不把不完整数据发布为成功快照。

### 8.3 重试与失败处理

- 网络超时、HTTP 429 和 5xx：指数退避加随机抖动，最多 5 次。
- 参数、权限、白名单、签名类 4xx：不自动反复重试，直接记录可操作错误。
- 每个数据域先写临时快照，完成分页、校验和转换后再原子发布。
- 任一核心数据域失败时保留最近一次成功版本，并将本次任务标记为 `partial` 或 `failed`。
- 日志保存 `traceId`、接口、市场、页码、开始/结束时间和错误分类；不得保存 `appKey`、完整 Token、签名或含隐私的请求体。

### 8.4 时间与币种

- 原始时间和积加返回的市场时间均保留；标准化时间统一存 UTC，页面按 Asia/Shanghai 展示同步时间，按站点本地时区展示经营周期。
- US、CA 分别使用接口返回币种。跨站总览默认分站显示；若后续增加折算总额，必须使用已有汇率配置并展示汇率日期。
- 月度数据只在完整月份参与同比、环比和季节性；当月数据明确标记“未结月”。

## 9. 页面需求

### 9.1 管理员后台：数据接入

新增“积加数据接入”区域，包含：

- 连接状态：白名单状态提示、凭证是否配置、最近一次成功鉴权时间。
- 数据源卡片：产品、经营、库存、广告、退货、采购、仓储费的最后成功时间、覆盖市场、记录数和新鲜度。
- “测试连接”与“立即同步”按钮；仅返回结果，不显示密钥。
- 同步历史：状态、耗时、数据域、记录数、重试次数、错误摘要和 `traceId`。
- 异常中心：未知 SKU、站点映射缺失、金额/库存冲突、分页中断、单位未确认。
- Excel 兜底导入和历史版本恢复沿用现有数据管理页面。

### 9.2 运营总览

- 默认展示 US，可切换 CA 和双站视图。
- 主指标使用销售额，不再以销售件数作为首要 KPI。
- 展示本月销售额、上月销售额、环比、实际利润、利润率、广告销售占比、退货率和库存覆盖。
- 每个指标显示统计周期、币种和最近同步时间。
- 双站金额不得直接混币相加，除非启用带日期的汇率折算。
- 页面不展示采购、发货、库存原始大表，只提供管理员后台入口。

### 9.3 单 SKU 经营简报卡片

卡片支持市场、父体、SKU、问题类型和搜索筛选。默认只展示需要关注和销售额贡献较高的 SKU，不一次列出全部 SKU；用户通过搜索或父体下钻查看其他 SKU。

每张卡片至少包含：

- SKU、产品名、父体、市场、数据周期和数据新鲜度。
- 最近 6 个月销售额趋势、最近售价和历史均价。
- 广告销售占比、广告花费占比、ACOS/ROAS。
- 退货率、退款率、月度仓储费及仓储费占销售额比例。
- FBA 可售、确认后的在途口径、现有补充库存、覆盖天数和库龄风险。
- 当前实际利润、利润率以及近 3 个月趋势。
- 1–3 条可解释建议，每条建议列出触发指标，不输出无法追溯的笼统结论。

建议示例：

- “近 3 个月销售额连续增长 18%，实际利润率 16%，库存覆盖 42 天：补货前先确认在途到仓日期。”
- “广告销售占比 64%，ACOS 39%，自然销售未同步增长：优先检查高花费低转化投放。”
- “退货率 8.2%，主要原因集中在尺寸不符：检查 Listing 尺寸表达和包装内说明。”

### 9.4 季节性口径

- 至少有 12 个完整月才展示季节性，24 个月为高置信度。
- 以 SKU 月销售额为主序列；销量仅作为价格变化校验。
- 季节指数 = 同月份历史销售额 / 对应历史年度月均销售额。
- 若月均售价变化超过 20%，同时显示销量趋势，避免把涨价误判为需求增长。
- 样本不足时显示“数据不足”，不得自动推断旺季。

### 9.5 普通成员供应链追溯

- 增加只读“供应链追溯”入口，支持按 SKU、采购订单号、出库/发货批次和供应商搜索。
- 出库视图显示每个 SKU 的出库数量，以及分别消耗了哪些采购订单/入库批次和数量。
- 仓库视图显示当前 SKU 库存由哪些采购订单/入库批次构成，包括入库量、累计出库、调整量、当前余量、入库日期和库存天数。
- 优先使用积加直接返回的订单、交货单和出入库关联；缺少直接关系时允许按同仓库、同 SKU、实际入库日期执行 FIFO 推算。
- 页面必须区分“系统直连、单据关联、FIFO 推算、人工确认、来源待核对”，不得把推算结果显示为已确认事实。
- 每个 SKU 的批次余量合计必须与当前仓库实盘数量对账；差异进入管理员异常中心，不自动摊入某张订单。
- 尚未实际入库的采购数量不得计入当前仓库库存构成。

## 10. 数据质量与可观测性

每次同步必须产出：

- 运行编号、代码版本、配置版本、开始/结束时间和状态。
- 每接口请求数、成功数、重试数、限流等待、读取行数、发布行数。
- 市场覆盖、SKU 覆盖、未知 SKU 数、重复记录数和缺失关键字段数。
- 原始快照哈希、标准报告哈希和上一个成功版本。
- 与上一快照相比的异常波动：销售额、库存、在途或利润变化超过配置阈值时进入复核，不阻断原始数据保存。

后台新鲜度标准：

- 库存超过 8 小时未更新：黄色；超过 24 小时：红色。
- 广告、退货、经营表现超过 36 小时：黄色；超过 72 小时：红色。
- 月度仓储费按月份判断，不使用小时级告警。

## 11. 安全要求

- `appId`、`appKey` 通过 NAS Docker secret 或仅服务器可读的环境变量注入；不得写入 Git、Compose 示例值、SQLite、日志或页面。
- 建议配置项：
  - `GERPGO_BASE_URL=https://open.gerpgo.com/api/open`
  - `GERPGO_APP_ID`
  - `GERPGO_APP_KEY`
  - `GERPGO_SIGNING_ENABLED=true`
- 生产环境白名单只允许 NAS 的固定公网出口 IP；需要先确认宽带公网 IP 是否稳定。
- 所有外部请求设置连接、读取和总超时。
- 管理员操作写审计记录；普通成员不能触发同步、修改映射或下载原始响应。
- 原始响应默认保留 30 天；订单数据在落盘前删除未用于分析的买家相关字段。

## 12. 对现有项目的实现约束

- 新增积加适配器放在 `automation/src/store_ops/` 下的独立集成模块；鉴权、HTTP、分页和业务转换分离。
- 新工作流以现有 CLI job 形式接入，沿用 `StateDb` 的运行和异常记录。
- 接入配置扩展现有 `automation/config/project.json`；环境和密钥只从环境变量读取。
- 标准化结果优先继续生成：
  - `runtime/reports/inventory_dashboard.json`
  - `runtime/reports/inventory_dashboard.ca.json`
  - `runtime/reports/profitability.json`
  - `runtime/reports/product_catalog.json`
  - `runtime/reports/purchase_plan.json`
- 如现有 schema 无法表达历史售价、每日广告或同步血缘，只做向后兼容扩展，不另建一套重复页面数据模型。
- API 导入和 Excel 导入共用相同的 SKU 标准化、校验、版本发布和恢复流程。

## 13. 验收标准

### 13.1 接入验收

- 使用生产白名单、签名和真实账户完成鉴权，Token 自动续期验证通过。
- US、CA 店铺映射由管理员确认并保存；代码中无硬编码 `marketId`。
- 所有 P0 接口支持完整分页、限流等待、失败重试和 `traceId` 记录。
- 在相同时间口径下随机抽取每站至少 20 个 SKU，与积加页面核对销售额、FBA 可售、广告花费和退货数量；金额汇总误差不超过 0.5%，数量必须一致。差异必须有可解释来源。
- 活跃 SKU 映射覆盖率不低于 98%；未映射记录进入异常中心。

### 13.2 产品验收

- 管理员能查看状态、手动同步、同步日志、异常和最近成功版本。
- 普通成员无法访问或调用同步管理接口。
- 外部接口不可用时，前台仍展示最近一次成功数据并明确标记过期。
- 运营总览主口径为销售额；SKU 卡片可以搜索，不默认平铺全部 SKU。
- SKU 卡片能同时展示售价、销售额、广告、退货、仓储、库存、利润和季节性证据。
- 普通成员能查看出库 SKU 的订单来源拆分，以及当前仓库库存的采购订单/批次构成，但不能修改归属和数量。
- 供应链页面明确显示订单构成的关联方式与对账差异。
- 页面显示来源和更新时间，API 值、手工覆盖值和 Excel 兜底值可区分。

## 15. 联调前必须确认的问题

1. FBA 库存 V2 的“灰度上线”是否已对当前积加租户开放，字段是否稳定。
2. `inTransitQty` 与 `inboundTotal` 在当前账户中的具体业务定义，本站应采用哪一个作为“在途”。
3. AWD 是否有单独仓库类型或接口；确认前不得用仓库名称自动猜测。
4. 产品列表中的长、宽、高、重量单位以及箱规字段是否与当前成本表一致。
5. 产品表现接口的利润是否已包含广告、退货、仓储、头程和税费，各字段结账延迟多久。
6. 产品表现可查询的最早日期、单次最大日期跨度以及历史修订周期。
7. 广告 ASIN 分析要求起止日期相同，是否允许稳定回溯 24 个月逐日数据。
8. 采购订单的剩余数量和预计交期应从列表还是详情接口读取。
9. 签名开关是否已在生产账户启用；启用后是否所有接口都强制校验。
10. NAS 的公网出口 IP 是否固定，变化时由谁维护白名单。
11. 出入库记录 V2 是否直接返回采购订单号、交货单号或入库批次；若没有，FIFO 推算应使用哪个实际入库时间字段。
12. 积加产品库存是否能按仓库返回可对账的物理库存，以及库存调整、报废和盘盈盘亏如何取得。

上述问题在阶段 A 形成联调记录后，才能把积加 API 提升为对应字段的默认事实源。
